# llm-creativity **Can you perturb an LLM into a genuinely different solution basin, or are you only sampling local variations of the same idea?** One weighted shortest-path task. Eight prompt strategies. 25 Claude Code subagents each, all on `claude-sonnet-5` — 200 programs, every one executed and classified by what its code does at runtime rather than by what it calls itself. Five of the eight strategies produced exactly one algorithm. ## Results | strategy | escape | 95% CI | p | lineages | unique algorithms | |---|--:|--:|--:|--:|--:| | `baseline` | 0.00 | [0.00, 0.00] | — | 1 | 1 | | `entropy_seed` — 64 random chars | 0.00 | [0.00, 0.00] | 1.000 | 1 | 1 | | `word_seed` — 8 random words | 0.00 | [0.00, 0.00] | 1.000 | 1 | 1 | | `semantic_seed` — Wikipedia / GitHub | 0.00 | [0.00, 0.00] | 1.000 | 1 | 1 | | `domain_analogy` | 0.00 | [0.00, 0.00] | 1.000 | 1 | 2 | | `explicit_creativity` — "be creative" | 0.16 | [0.04, 0.32] | 0.116 | 3 | 4 | | `gen_then_select` — external RNG picks | 0.36 | [0.16, 0.56] | **0.0005** | 4 | **10** | | `negative_memory` — ban what was used | **0.96** | [0.88, 1.00] | **0.0002** | 4 | 6 | *Escape* = P(major lineage ≠ the baseline's modal branch, `cost_priority`), with a 4,000-sample bootstrap CI and a two-sided permutation test against baseline. Three findings worth the setup: \- **Seeding does nothing.** Random characters, random words and real Wikipedia text all returned Dijkstra 25/25, exactly like asking plainly. 100 consecutive generations, zero basin changes. \- **Escape rate alone is misleading.** `negative_memory` has the highest escape and the *lowest* spread of anything that moved — 16 of its 25 landed on SPFA, and 19 of 25 repeated a mechanism already on the ban list they were shown. Banning the attractor manufactures a new attractor. `gen_then_select` escapes less but spreads much wider (1.43 bits of lineage entropy vs 0.87; mean pairwise distance 0.359 vs 0.216). \- **The bottleneck is selection, not generation.** Asked to list mechanisms, the model readily names Dial's algorithm, Floyd–Warshall, Bellman–Ford. Allowed to choose, it takes Dijkstra almost every time. Removing the choice beat every prompt we wrote. Escaping costs correctness: baseline is 25/25 optimal, `explicit_creativity` 16/25. The task has non-negative weights and no coordinates, so no admissible heuristic exists and Dijkstra is genuinely right. This attractor is a *justified* one. ## Reports \- **[index.html](index.html)** — short report, served via GitHub Pages \- **[reports/the-dijkstra-attractor.html](reports/the-dijkstra-attractor.html)** — full technical report: all metrics, CIs, permutation tests, lineage tree, caveats \- **[analysis/REPORT_T1.md](analysis/REPORT_T1.md)** — generated markdown + three figures ## How it works Everything is held fixed except the perturbation: same model, same task text, same output contract, same evaluator. Seeds are deterministic from one master seed; Wikipedia extracts and GitHub READMEs were fetched live and cached to `data/seeds/semantic.json`. Each solution is reduced to a **mechanistic fingerprint** over 11 categorical axes — trajectory, stochasticity, coverage, heuristic, frontier structure, state scope, backtracking, memory, adaptation, topology, learning — and placed in a lineage tree by mechanism.
