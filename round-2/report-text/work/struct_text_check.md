This run asks what decides which algorithm an open-weight instruction-tuned model writes for a coding task, and what a `Do not use X` instruction does to that choice inside the model. On two path search tasks Qwen3-8B writes BFS and Dijkstra almost always; sampling temperature, top-k, thinking mode and random seeds change the wording of the code but not the algorithm, even with seeds held fixed across temperatures. A single prompt ban makes the model collapse again on one substitute, Bellman-Ford/SPFA in all 272 compliant programs across five draws and DFS in most grid draws; how often a ban is obeyed depends mainly on its wording, and bans of four or five names fail because the model reimplements the banned defaults. KV cache patching shows that the ban is applied by the prompt states before the first generated token, mostly as a veto on the default program's first line (prompt route 0.85 of the banned algorithm's likelihood drop, direct route 0.00), with an additional direct read of the ban during generation on the grid task. What decides the replacement is still open: forward pass likelihoods in Qwen3-8B and Llama-3.1-8B-Instruct show that ban gains are neither pure subtraction nor a coherent ladder of survivors, their X specific share is undetermined, and on the shortest path task random activation edits reach the same substitute as the ban. No ban or diversity knob buys a second correct algorithm for under 20 points of pass rate. A 12-task confirmation bench is frozen; Qwen3-8B is fully collapsed on all of it.
