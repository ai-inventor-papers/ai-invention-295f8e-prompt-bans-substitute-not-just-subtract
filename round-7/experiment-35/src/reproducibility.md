# Reproducing "Where temperature can change the chosen algorithm" (iteration 7, claim T)

This file records what was actually run, in order, with the real commands, seeds, hardware and timings. Every path is
relative to this artifact's folder.

## 1. Get the artifact

This workspace is published as one folder of a public GitHub repository. Clone the repository and `cd` into this
artifact's folder:

```bash
git clone <repository-url>
cd <repository>/<this-artifact-folder>        # the folder that holds method.py, README.md and this file
```

- **Prior-artifact inputs.** The inputs this pipeline reads from earlier artifacts are already in the folder, under
  `inputs/`, with sha256 sums in `inputs/input_hashes.json` and `inputs/SHA256SUMS`. A reader does not need the
  original server.
- **Declared dataset dependency `art_j3Rm_lr2nzR6`** (source data for an algorithm-choice coding bench):
  - It is read through ONE constant, `DEP_DIR` in `src/cfg7.py`: the environment variable `ART_J3RM_DIR`, else the
    sibling folder `../art_j3Rm_lr2nzR6` of the published repository.
  - Its extract, `inputs/dep_extract.json` (195 relevant rows from all ten datasets), is already published, so the
    novelty audit runs without it.
- **User uploads.** None were used (the run's upload folder was empty).

## 2. System, Python and libraries

Hardware actually used:

- one NVIDIA GeForce RTX 4090 (24 GB VRAM, driver 595.91.07);
- 11 CPU cores (container quota of an AMD Threadripper 7960X);
- 57 GB RAM (container limit).

The plan assumed an RTX A4500 with 20 GB. Any CUDA GPU with at least 20 GB of free VRAM runs the whole bf16 model;
with less than 18 GiB free the loader keeps the input-embedding table on the CPU (exact).

Software actually used:

- OS: Debian GNU/Linux 12 (bookworm) in a container; Ubuntu 22.04 or 24.04 works the same.
- Python 3.12.14.

- 85 packages, all pinned in `pyproject.toml`, generated by `uv pip freeze --python .venv/bin/python`. The main ones:
  - torch 2.8.0 (PyPI CUDA 12.8 build), transformers 4.57.6, tokenizers 0.22.2, safetensors 0.8.0, accelerate 1.15.0,
    huggingface-hub 0.36.2;
  - numpy 2.2.6, scipy 1.18.1, matplotlib 3.11.2;
  - openai 3.35.1 (OpenRouter client), loguru 0.7.3.

`method.py all` runs steps 1-13 in order: vendor, prompts, gputests, twins, cputests, commit0, forkscan, commit1,
predict, commit2, generate, finalize. The commit stages refuse to overwrite an existing commit, so a full rerun in a
copy of this folder needs `commitments.log` and `predictions/commit*.json` removed first.

`method_out.json` was then checked against the `exp_gen_sol_out` schema, and its `full_`, `mini_` and `preview_`
variants were written with the AI Inventor aii-json skill scripts:

- `mini` = the first 3 examples of each dataset;
- `preview` = mini, with every string truncated to 200 characters.

Both files are under 100 MB (10.9 and 13.4 MB), so nothing was split.

**Seeds and determinism.**

- **Sampling.** Every uniform comes from `u_stream(*key)`, a PCG64 seeded with sha256 of the key (`src/cfg7.py`). The
  keys are:
  - `('iter7T', unit, template, slot)` for programs;
  - `('iter7fork', unit, base_path, prefix_len, j)` for continuations;
  - the iteration-6 keys `(task, template, slot)` for the engine check.
- **Other seeds.**
  - Base paths: `random.Random(20261022)`.
  - Residual-bin first tokens: PCG64 seeded with `stable_seed('resid', unit, cluster)`.
  - MR draws: `stable_seed('MR', unit, slot)` for the generated arms; `('MR_tf', unit)` for the teacher-forced numbers.
  - Bootstraps: seed 20261022.
  - `torch.manual_seed(0)`, although the sampler does not use torch randomness.
- **Repeat runs.** With the same GPU class and the same batch composition, generation is bit-reproducible: G2 gave
  10/10 identical programs.
- **Batch size.** Changing the batch size changes about 30% of token sequences, which is kernel sensitivity (G3). Every
  same-seed comparison therefore uses one fixed batch composition: sweep batches hold the 4 temperatures x 10 slots of
  one template.
- **Another GPU.** On a different GPU class, expect per-slot agreement of about 0.95 (iteration 6 vs this run:
  T2 0.95, T03 0.95), not bit identity.
- **Judges.** They run at temperature 0. Provider-side nondeterminism is possible, which is why every adjudication is
  stored.
