\title{A Random Activation Push Changes a Code Model's Algorithm Where Temperature Does Not}
\author{}
\date{}

\begin{document}

\maketitle

\begin{abstract}
Sampling temperature is often treated as the creativity control of a language model. We ask whether it changes which algorithm a code model implements, rather than how the model writes the same algorithm. On shared random streams, we compare temperature in Qwen3-8B with a random push of the residual-stream states at the prompt tokens that specify the task, and we label every program by its runtime behaviour on hidden tests. The push changed the algorithm in more seeds than temperature did, by a paired difference of 0.545 per seed (95\% CI 0.41 to 0.67) pooled over shortest path and $k$-th smallest. This contrast was preregistered and held in a single experiment whose overall preregistered verdict is partial, because the push fell short of its predicted effect on $k$-th smallest; it ran only in an 8-bit (W8A8) engine and is untested in bfloat16. Temperature from 0.3 to 1.3 changed the algorithm in none of 20 seeds on each of three tasks while the number of phrasings grew, a null also observed in thinking mode and in bfloat16. Prefix resampling shows why: one or two forking tokens settle the algorithm, and on these tasks the default leads there by several nats, more than this temperature range can overcome. Where the forking token is contested, a law built from its logits and committed before sampling predicted the temperature response on five of six units, including two held-out Gemma-3-4B units, though a baseline that predicts no change was nearly as accurate. No control applied to single samples produced a correct novel algorithm; with an evaluator selecting programs across generations, one bin packing search yielded eight programs that its manual read classed as a new idea, which an independent replication did not reproduce. For diversity evaluations, the results locate where randomness reaches the algorithm: at the forking token and upstream of it. Inside program search, forcing a branch at the position of highest entropy found more distinct behaviours per call than sampling at temperature 1.0 on bin packing but not on a travelling salesman task, and its advantage over forcing a branch at a random position did not replicate.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Ask Qwen3-8B~\citep{Yang2025} to implement a path search on a grid and it writes breadth-first search (hereafter BFS) in 99 of 100 programs; ask it for a weighted shortest path and it writes Dijkstra's algorithm in 100 of 100. The model knows the alternatives: when asked to list ten approaches before implementing one, Qwen3-8B names every grid algorithm in our catalogue in 100 of 100 lists.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-1/experiment-6}} It simply does not use them. This paper asks which inference-time controls change the algorithm such a model implements, as opposed to the way it writes the same algorithm, and where inside generation that choice is made.

The question matters because many uses of code models depend on drawing different solutions rather than different spellings of one solution. Choosing the best of $n$ samples and program search with an automatic evaluator~\citep{RomeraParedes2023,Novikov2025} rely on sampling to explore the space of approaches, and creativity benchmarks measure how far it does~\citep{Lu2025,Zhang2025}. Output diversity is known to narrow after alignment, a pattern called generative monoculture~\citep{Wu2024}, and code models concentrate on a few algorithms among correct programs~\citep{Lee2025,Narula2026}. Sampling temperature is the control most often raised to counter this, and it is often described as the creativity parameter of a language model~\citep{Peeperkorn2024}.

Answering the question is harder than counting distinct outputs. Two programs can differ in every line and implement the same algorithm, and a program can name one algorithm while executing another, so labels must come from what the code does when run. Comparisons across temperatures drawn with independent random numbers mix the effect of temperature with sampling noise; with a default share near 1.0, a few stray samples look like a temperature effect. And knowing that an algorithm changes says nothing about where the decision was made: in the prompt representation, at some point during generation, or diffusely across the program.

Prior work leaves these pieces apart. Algorithmic diversity has been measured across sampling settings with independent samples~\citep{Lee2025}, and the gap between approach-level and surface-level diversity has been documented for mathematical reasoning~\citep{Lee2026}. Forking tokens, positions where resampling changes the outcome distribution, have been found in text generation~\citep{Bigelow2024}, and post-training shifts are known to concentrate at a few high-entropy tokens~\citep{Meng2026,Wang2025}. No study we know of has located the token that decides which algorithm a code model writes, predicted from it what temperature will do before sampling, or measured temperature against an internal perturbation under one shared random stream.

We hold one random stream fixed per seed across conditions (common random numbers), label every program by its runtime behaviour on hidden tests, and locate forking tokens by prefix resampling. On the same streams, a random push of the task specification states of the prompt changed the algorithm Qwen3-8B writes in more seeds than temperature did, by 0.545 per seed (95\% CI 0.41 to 0.67) over shortest path and $k$-th smallest, a preregistered contrast that held, run only in an 8-bit engine and untested in bfloat16 (Figure~\ref{fig:headline}). Temperature from 0.3 to 1.3 never changed the algorithm in any of 20 seeds on three tasks where the model writes one default algorithm, while the number of distinct phrasings grew. The algorithm is settled at one or two forking tokens after a shared opening, and on the default tasks the default leads there by 4.85 to 17.04 nats, far more than temperature in the range 0.3 to 1.3 can overcome. Where the forking token is contested, a law composed from its teacher-forced logits predicts how temperature moves the mix. Our results cover one main model family, a small set of tasks, and a temperature law tested on only three held-out units, two of which passed.

\paragraph{Summary of contributions.}
\begin{itemize}
  \item \textbf{A task-state push changes the algorithm where temperature does not (Section~\ref{sec:res-push}).} On the same random streams, a random task-state push, that is, one random direction added to the task specification states (Section~\ref{sec:crn}), changed the algorithm in more seeds than temperature did, by 0.545 per seed (95\% CI 0.41 to 0.67), pooled over shortest path and $k$-th smallest (40 seeds). The contrast was preregistered and held (sign flip test, $p = 1.0\times10^{-5}$) in an experiment graded partial, and it ran only in an 8-bit (W8A8) engine. Temperature 0.3 to 1.3 changed the algorithm in 0 of 20 seeds on each of three tasks while phrasing clusters on the grid task rose from 3 to 13, a null that replicates in thinking mode, over 800 independent samples per task and, at the forking token, in bfloat16.
  \item \textbf{One or two forking tokens settle the algorithm (Section~\ref{sec:res-fork}).} Given the class of the forking token, at most 0.19 bits of uncertainty about the algorithm remain; on four default tasks the fork margin (Section~\ref{sec:fork}) is 4.85 to 17.04 nats.
  \item \textbf{A composed forking-token law predicts temperature's effect (Section~\ref{sec:res-law}).} Committed before sampling, it matched the observed algorithm distribution across four temperatures within a mean total variation distance of 0.014 to 0.054 on five of six units, including two held-out Gemma-3-4B units, and failed on Llama-3.1-8B's grid task (0.142). A baseline that predicts no change was close (the law was better on four of six units).
  \item \textbf{The task specification states and post-training set the fork (Section~\ref{sec:res-sets}).} Writing the task specification states of a prompt that names the minority algorithm into a copy without that instruction, with its token positions aligned, produced the minority algorithm in 30 of 30 samples on each of three tasks. On the three default tasks, post-training widened fork margins by 2.11 to 13.41 nats relative to the base model while changing the entropy at phrasing positions by less than 0.5 nats.
  \item \textbf{Other controls reweight the same repertoire (Sections~\ref{sec:res-other} and~\ref{sec:res-geometry}).} Random seeds, novelty instructions, bans, activation pushes and program search moved programs among known algorithms. No audit of a control applied to single samples found a correct novel algorithm; eight bin packing programs from one program search were classed as a new idea, and a replication found none. Where a ban of five names lands in activation space depends on whether the map is built from names or from programs.
\end{itemize}

\section{Related Work}
\label{sec:related}

\paragraph{Diversity collapse and creativity in code models.} Alignment narrows output diversity relative to the variety available for a task~\citep{Wu2024,Kirk2023}, reduces conceptual diversity~\citep{Murthy2025}, and leaves base models better at randomness and creative generation than their aligned descendants~\citep{West2025}. The structure of the chat format alone contributes to this collapse~\citep{Yun2025}. The typicality bias learned from human preferences has been linked to mode collapse that verbalized sampling partly undoes~\citep{Zhang2025a}. In code, \citet{Lee2025} find that models concentrate on few algorithms among correct solutions, and \citet{Narula2026} show that subtle prompt cues steer which algorithm is chosen. Denial prompting, which forbids the technique of the previous solution, is used to measure creativity in code generation~\citep{Lu2025}. Benchmarks of humanlike diversity~\citep{Zhang2025} and the distinction between approach-level and surface-level diversity in mathematical reasoning~\citep{Lee2026} motivate counting ideas separately from phrasings. We adopt that separation for code, with ideas defined by runtime behaviour, and we measure it under coupled randomness so that the effect of a control on a single sample can be read directly. Our behavioural design follows an open repository of creativity experiments with language models,\footnote{\url{https://github.com/DrejcPesjak/llm-creativity}} which asked a closed model for weighted shortest path programs under context seeds, creativity instructions and cumulative bans.

\paragraph{Temperature and decoding.} Truncation samplers such as nucleus sampling~\citep{Holtzman2019} and min-p sampling~\citep{Nguyen2024} shape the token distribution at each step, and adaptive schemes raise temperature only where the next token is hard to predict~\citep{Zhu2024,Zhang2024}. \citet{Peeperkorn2024} find that temperature correlates only weakly with novelty in story generation. In code, \citet{Lee2025} report that temperature above 1 raises algorithmic diversity, and \citet{Sohail2025} observe more distinct operations in generated sorting algorithms as temperature rises from 0.75 to 1.1. Intent factored generation and plan search diversify a sampled intent or plan before writing~\citep{Ahmed2025,Wang2024}, random embeddings injected into the input diversify reasoning paths~\citep{Kim2026}, and the level at which randomness enters a generation pipeline changes how diverse its outputs are~\citep{Zhang2026}. In diffusion language models, an idealized model of fork tokens motivates tempering the choice of which position to unmask, rather than the token distribution, to keep entropy at the forks~\citep{Olausson2026}. Coupling counterfactual generations through shared Gumbel noise~\citep{Ravfogel2024} is the closest precedent for our common-random-numbers design. Our contribution is to explain why temperature does or does not reach the algorithm, and to predict the size of its effect from one token's logits before sampling.

\paragraph{Where an output is decided.} Forking Paths analysis resamples continuations from prefixes and finds tokens after which the outcome distribution changes abruptly~\citep{Bigelow2024}. Thought anchors identify the reasoning sentences whose resampling matters most~\citep{Bogdan2025}. A small set of high-entropy minority tokens carries most of the effect of reinforcement learning on reasoning~\citep{Wang2025}. Post-training shifts concentrate at a few tokens~\citep{Meng2026}, aligned models mostly reproduce the base model's top token at ordinary positions~\citep{Lin2023}, and learned behaviours can be enforced in the first few response tokens~\citep{Qi2024}. Self-improvement and post-training have been described as sharpening probability onto outputs the base model already ranks highly~\citep{Huang2024}. We extend this line to the algorithm a program implements: we locate its forking token blind, compose a temperature law over it, and measure how far post-training moved that token relative to ordinary positions.

\paragraph{Interventions on internal states and program search.} Activation steering adds a direction to the residual stream~\citep{Rimsky2024,Arditi2024}, distributed alignment search fits subspaces in which interchange interventions reproduce a counterfactual~\citep{Geiger2023,Wu2023}, and such subspace edits can act through pathways the model does not use naturally~\citep{Makelov2023}. Activation steering has also been turned into an exploration method that pushes the hidden states of concurrent generations apart, which raises the diversity of reasoning paths and of generated test cases~\citep{Khanh2026,Zhu2026}. Representation geometry is studied with geodesic distances and Isomap~\citep{Tenenbaum2000} and, recently, manifold steering~\citep{Wurgaft2026}; sparse autoencoders~\citep{Lieberum2024} and the tuned lens~\citep{Belrose2023} read intermediate states. Program search with a language model as mutator and an automatic evaluator has found new constructions and heuristics~\citep{RomeraParedes2023,Novikov2025,Liu2024,Ye2024}. We use activation edits as tests of where the algorithm is set rather than as a diversity method, and we audit every correct program outside each task's catalogue for novelty.

\label{sec:method}

A temperature law is composed from that token's logits (Section~\ref{sec:law}). Activation exchanges test what sets the token (Section~\ref{sec:probes}).

\subsection{Tasks, models and algorithm labels}
\label{sec:labels}

The study starts from two path search tasks. In the grid task, \code{solve(grid, start, goal)} returns a valid path on a grid with walls; its catalogue holds BFS, depth-first search (hereafter DFS), bidirectional BFS, iterative deepening DFS, A* and unit weight Dijkstra, that is, Dijkstra's algorithm with every edge weight set to one. The weighted shortest path task works on a directed graph, with a catalogue of Dijkstra, Bellman-Ford with its queue variant SPFA, bidirectional Dijkstra, Floyd-Warshall and Dial's algorithm. Each has 40 to 48 seeded hidden test cases with a time limit per case, and reference implementations of every catalogue algorithm that pass all tests.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-1/experiment-1}} A further 13 tasks, the \emph{bench} below, were derived from LeetCode problems with frozen wording and catalogues of 3 to 6 algorithms each, 684 hidden test cases in total, and references for all 54 catalogue algorithms.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-2/experiment-11}} The tasks used below are $k$-th smallest element (default: full sort), connected components (default: union find), minimum spanning tree weight (Kruskal or Prim), trapped rain water (prefix and suffix maxima or two pointers) and valid anagram (sort and compare or counting), plus substring search and first and last position in a sorted array for Gemma. A \emph{unit} is a task paired with one model. We call a unit a \emph{default task} when the instruct model writes one algorithm in essentially all samples, and a \emph{mixed unit} when its unperturbed samples already contain a second algorithm at a share of roughly 0.1 to 0.4.

The main model is Qwen3-8B~\citep{Yang2025} in non-thinking mode unless stated, with Qwen3-8B-Base for the post-training comparison. Held-out units come from Gemma-3-4B (gemma-3-4b-it, Gemma below) and Llama-3.1-8B (Llama-3.1-8B-Instruct, Llama below)~\citep{Grattafiori2024}, and Qwen3-14B and Qwen3-32B with thinking enabled enter the ban experiments. Generation used vLLM~\citep{Kwon2023} or a Hugging Face engine in bfloat16 or with 8-bit floating-point linear layers, stated per experiment.

A program's \emph{algorithm label} comes from a sandboxed runtime tracer that records queue, stack and heap operations, edge relaxations and grid reads, combined with AST rules; a blind LLM judge breaks disagreements. Labellers were gated on references and adjudicated gold sets before use. On the bench tasks, agreement between the runtime and AST labellers reached Cohen's $\kappa$ 0.84 to 1.00, with every reference correctly labelled. On the path tasks the combined label agreed with the adjudicated gold label at $\kappa = 0.966$ with 22 of 22 references correct, although the stricter criterion of that gate, agreement between the runtime and AST labellers ($\kappa = 0.753$), was not met. A program is correct when it passes every hidden test.

\subsection{Ideas and phrasings}
\label{sec:ideas}

We call the runtime label of a correct program its \emph{idea}. A \emph{phrasing cluster} is a connected component, within one idea, of programs whose AST 4-gram shingle sets, computed with normalised identifiers, have Jaccard similarity at least $\theta$; identifiers are renamed in order of appearance, and comments, docstrings and constants are dropped. $\theta = 0.8$ is primary, with 0.7 and 0.9 as sensitivity values. We call the number of phrasing clusters within an idea its \emph{phrasings}. Diversity over ideas is the Hill number of order 1 (Hill-1), the exponential of the Shannon entropy of the idea distribution~\citep{Hill1973}, computed among correct programs and rarefied to a depth of 25 programs. The \emph{number of ideas at depth 25} is the expected count of distinct ideas among 25 correct programs drawn from a cell.

\subsection{Common random numbers}
\label{sec:crn}

Every comparison of decoding conditions samples by inverse transform sampling with common random numbers: each seed owns one stream of uniform variates, and every condition maps the same variates through its own next-token distribution. A difference between two conditions on one seed is therefore caused by the condition, not by a different draw. For a block of conditions, the \emph{change count} of a task is the number of seeds whose algorithm label differs anywhere across the block; we bound its rate with the Clopper-Pearson interval~\citep{Clopper1934}. Thinking-mode arms ran in vLLM with a seed set for each request, which couples conditions through shared Gumbel noise~\citep{Ravfogel2024}.

The temperature block ran each of 20 seeds per task (spread over five prompt templates) at $T$ = 0.3, 0.7, 1.0 and 1.3 with top-$p$ 1, and as sensitivity conditions with top-$k$ 10 at $T = 0.7$ and with min-$p$ 0.1 at $T = 2.0$.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-4/experiment-21}} The comparison intervention is a random activation push: activation addition with a random rather than a learned direction, akin to noise steering. We call it a \emph{random task-state push}: one isotropic unit direction is added, during the prefill only, to the residual stream activations at the token positions that state the task (the \emph{task specification states}) in blocks 12 to 23. Its size is set in multiples $\alpha$ of the displacement that a ban prompt induces at the same positions. Six fixed directions were run at $\alpha = 1$ and 2.

\subsection{Locating the forking token}
\label{sec:fork}

Programs of different algorithms often share their first tokens; we call this common prefix the \emph{shared opening}. Following Forking Paths analysis~\citep{Bigelow2024}, we sample base programs, resample continuations from their prefixes at increasing lengths, label every completed continuation, and detect a change point in the algorithm distribution with a preregistered Bayesian rule calibrated against permutation nulls. The change point is refined to a single token and confirmed by forcing each candidate token and sampling continuations from it. When the branch after a forking token is not pure, a second forking token is searched inside it. Below, \emph{the fork} is short for the forking token. We define the \emph{fork margin} as the teacher-forced gap in log probability, at the forking token, between the class of tokens that lead to the default algorithm and the best class that leads elsewhere, and report $H(A \mid \text{class})$, the entropy of the algorithm given the forking token's class.

\subsection{A composed temperature law}
\label{sec:law}

Let $O_c$ be the $c$-th shared opening that precedes a forking token, and $w_T(O_c)$ the probability of sampling it at temperature $T$, the product of tempered teacher-forced token probabilities along it. Let $\pi_T(t \mid O_c)$ be the tempered next-token distribution at the fork, renormalised over the top 10 logits for top-$k$ 10, and $P(A \mid t)$ the share of algorithm $A$ among $T = 1$ continuations forced from token $t$. We call the prediction
\begin{equation}
P_T(A) = \sum_c w_T(O_c)\Big[\sum_t \pi_T(t \mid O_c)\, G(t, A) + r_T(c)\, P(A \mid \mathrm{rest}_c)\Big] + \Big(1 - \sum_c w_T(O_c)\Big)\, q_{\mathrm{rest}}(A)
\label{eq:law}
\end{equation}
the \emph{composed law}. Here $G(t, A) = P(A \mid t)$ unless $t$ opens a second fork, in which case $G$ is the same mixture taken over the second fork's tokens. The term $r_T(c)$ is the tempered mass outside the top 20 tokens, and $q_{\mathrm{rest}}$ is the composition of samples that leave the located openings. The prediction is averaged over five prompt templates and uses only teacher-forced logits and $T = 1$ conditionals, so it can be committed before any temperature sample is drawn.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-8/experiment-43}}

Four rivals were committed with it: a flat law that keeps the $T = 1$ shares at every temperature; a rival we call share tempering, which raises the $T = 1$ shares to the power $1/T$ and renormalises; a single fork law without the second level; and the same law at the position of highest entropy instead of the located fork. Each predictor is scored by its mean absolute error (MAE), the mean over the four temperatures of the total variation distance between predicted and observed label distributions.

\subsection{Probing what sets the forking token}
\label{sec:probes}

\paragraph{Task-state exchange.} We call the following interchange intervention a \emph{task-state exchange}. A forced prompt (\texttt{Implement the task with $\langle$minority algorithm$\rangle$}) is paired with a \emph{padding twin} in which the instruction is replaced by padding tokens so that all positions align. We write the task specification states of the forced prompt into the forward pass of the twin and sample on shared streams, against a random exchange matched in norm.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-7/experiment-35}}

\paragraph{Base against instruct.} Qwen3-8B and Qwen3-8B-Base are teacher-forced on identical token ids formatted with the chat template, at the forking tokens and at 64 phrasing positions of 20 programs per task. We compare fork margins, next-token entropies and Jensen--Shannon divergences, and count how often the token of the instruct model is the top token of the base model, following the URIAL token categories~\citep{Lin2023}.

\subsection{Other controls and the novelty audit}
\label{sec:controls}

To bound the result we also measured random context seeds (\code{seed=d32qxk4nt43} and \code{seed=(horse chair roof love)} prepended to the prompt) and a \emph{semantic seed}, a paragraph that implies an algorithm without naming it. We further measured instructions from \code{be creative} to a 2,000-word request for a fully novel algorithm, and \emph{bans}, instructions not to use a named algorithm, either of the default alone or of five algorithms at once (we call the latter a \emph{ban of five names}). A \emph{survivor} is a correct program whose algorithm is not banned. Finally, we ran an island-model program search in the manner of FunSearch~\citep{RomeraParedes2023}, in which the model mutates programs and a fixed evaluator keeps the best ones across generations. Every correct program labelled outside its task's catalogue was compared with a corpus of known solutions (about 18,000 programs built from LeetCode, textbook and benchmark solutions), read by blind LLM judges gated on known controls, and read manually. Zero novel programs in $n$ correct ones is reported with the rule-of-three bound $3/n$.

\section{Experimental Setup}
\label{sec:setup}

\paragraph{Preregistration.} Every decisive prediction, threshold and analysis rule was written to a SHA-256 hash chain before the samples it governs were drawn, and each artifact's chain verifies end to end. The experiment with shared seeds preregistered four predictions: a temperature change count of at most 1 of 20 seeds in each of four cells (three tasks without thinking, shortest path with thinking); phrasings per idea that grow with temperature; a random push that changes at least 5 of 20 seeds on shortest path and on $k$-th smallest; and a positive contrast per seed between push and temperature, pooled over those two tasks, at one sided $p < 0.05$, which was the experiment's single entry in its secondary family of preregistered tests. The experiment is confirmed only if all four hold. The composed law's criterion was an MAE of at most 0.10 with $H(A \mid \text{class})$ at most 0.3 bits per unit, and passing on at least 70\% of scored units including at least 3 held-out units, with at least 4 held-out units scored.

\paragraph{Units and samples.} The temperature block used 20 seeds per task and condition for Qwen3-8B on grid, shortest path and $k$-th smallest, run in an 8-bit engine whose rows reproduced the same cells of an earlier run token for token (200 of 200). The composed law was developed on trapped rain water, valid anagram and minimum spanning tree weight in Qwen3-8B and tested, before any Qwen3-8B sweep sample, on held-out units from two other families: substring search and first and last position in gemma-3-4b-it, and the grid task in Llama-3.1-8B-Instruct. Each unit was swept on 100 fresh shared streams at $T$ = 0.3, 0.7, 1.0 and 1.3 under top-$p$ 1 and top-$k$ 10, in bfloat16. Algorithm changes under activation pushes are not an artefact of the 8-bit engine: push directions move the algorithm about as often in bfloat16 as in the 8-bit engine (26 of 40 directions escape, by the criterion of Section~\ref{sec:res-other}, on connected components against 29 in the 8-bit engine, and 6 against 8 on shortest path).\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-6/experiment-29}}

\paragraph{Statistics.} Paired binary contrasts use the exact McNemar test~\citep{Mcnemar1947}; the contrast per seed between push and temperature uses a sign flip test, a permutation test that flips the sign of each seed's difference, with a bootstrap interval over seed slots; and proportions use Wilson or Clopper-Pearson intervals. Every headline number was rederived from raw rows by an independent script sharing no code with the analysis, and placebo versions of each test (shuffled conditions, shuffled temperature labels, shuffled token maps) were run and rejected at about their nominal rate. Code, prompts, raw generations, labels and the hash chains of every experiment are released with the paper, and each result below links to the code that produced it.

\section{Results}
\label{sec:results}

\subsection{A task-state push changes the algorithm where temperature does not}
\label{sec:res-push}

On the same random streams, a random task-state push, that is, one random direction added to the task specification states, changed the algorithm of Qwen3-8B in more seeds than temperature did, by a paired difference of 0.545 per seed (95\% bootstrap CI 0.41 to 0.67), pooled over shortest path and $k$-th smallest (40 seeds; Figure~\ref{fig:headline} and Table~\ref{tab:seed}). For each seed, the contrast is the push's change indicator, averaged over the 20 subsets of three directions (each a union over its three directions at $\alpha = 1$ and $T = 1.0$), minus the seed's change indicator across the four temperatures. It was the experiment's single entry in its secondary family of preregistered tests, and it held, with a one sided sign flip $p$ of $1.0\times10^{-5}$. A permutation of conditions within each seed never reaches the observed mean (maximum placebo mean 0.155 in 200 permutations). The experiment as a whole is graded partial: its preregistered prediction that the push changes at least 5 of 20 seeds held on shortest path (17.25) but failed on $k$-th smallest (4.55). The contrast was run only in the 8-bit (W8A8) engine and was not rerun in bfloat16. The push itself does change the algorithm in bfloat16 at the same absolute push norm (Section~\ref{sec:setup}).

A single push direction at $\alpha = 1$ changed 7, 10, 15, 17, 3 and 8 of 20 seeds on shortest path and up to 7 of 20 on $k$-th smallest. The algorithms the changed programs moved to, their \emph{landings}, were Bellman-Ford/SPFA (52 of 60 programs off the default on shortest path) and quickselect (11 of 11 on $k$-th smallest). The push is not free: pass rates on shortest path fell from 1.00 to 0.63 at $\alpha = 1$ and 0.42 at $\alpha = 2$.

Temperature, on the same seeds, never changed the algorithm on any of the three default tasks. Across $T$ = 0.3, 0.7, 1.0 and 1.3, all 20 seeds kept their algorithm on shortest path (Dijkstra), on $k$-th smallest (full sort) and on the grid task (BFS). The change count is 0 of 20 per task, with an exact 95\% upper bound of 0.168 on the change rate per seed. This was a separate preregistered prediction (at most 1 of 20 seeds per cell), and it held under every reading: counting only correct programs, counting invalid outputs as a label, and adding top-$k$ 10 as a fifth condition all leave the count at 0. Adding min-$p$ 0.1 at $T = 2.0$ changes one seed on shortest path and one on $k$-th smallest. With thinking mode enabled, shortest path kept Dijkstra in 20 of 20 seeds, every final program and every first approach named in the thinking trace was Dijkstra, and all 100 traces completed within the 16k-token cap. The reduced grid arm kept BFS in 10 of 10 seeds.

Phrasings, in contrast, grow with temperature (Figure~\ref{fig:phrasings}). On the grid task the number of phrasing clusters among 20 programs rose from 3 at $T = 0.3$ to 10, 12 and 13 at $T$ = 0.7, 1.0 and 1.3, while the number of distinct algorithms stayed at 1 on all three tasks at every temperature. The pooled slope of log phrasings per idea on temperature is 0.70 per unit $T$ (95\% CI 0.35 to 0.93) at Jaccard threshold 0.8, and 0.64 [0.30, 0.89] and 0.81 [0.33, 0.98] at 0.7 and 0.9. Almost all of the growth comes from the grid task, while shortest path moves from 1 to 2 clusters and $k$-th smallest stays at 2.

The temperature null replicates outside the design with common random numbers and outside the 8-bit engine. With 100 independent samples per cell, 797 of 800 grid programs were BFS and 797 of 800 shortest path programs were Dijkstra across eight temperature and sampler cells in non-thinking mode, and 800 of 800 in thinking mode. Over the same cells, grid phrasing clusters at threshold 0.8 rose from 4 to 36 with top-$k$ 10 and from 3 to 24 with top-$p$ 0.95. The literal setting of thinking mode with top-$k$ 10 under one seed per stream again changed the shortest path algorithm in 0 of 20 seeds (one sided 95\% upper bound 0.139),\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-5/experiment-27}} and in bfloat16, 100 samples at $T = 1.3$ from the forking position left the default unchanged on four tasks (Section~\ref{sec:res-fork}). At tight temperature the model therefore writes one idea in a few phrasings, and loosening temperature multiplies the phrasings of that idea rather than adding ideas.

Which default a model writes depends on the model. Asked for a path search on a grid, Qwen3-8B writes BFS in 99 of 100 programs at $T = 1.0$ and Dijkstra in 100 of 100 on weighted shortest path. \subsection{One or two forking tokens settle the algorithm}
\label{sec:res-fork}

Prefix resampling places the decision at a single token after a shared opening on every unit where the instruct model writes two algorithms (Table~\ref{tab:law}, fourth column). On minimum spanning tree weight the 61-token opening is followed by the word after the comment marker \code{\#}: \tok{Kr} (probability 0.72) leads to Kruskal in every continuation, and \tok{Prim} (0.27) to Prim in 97\%. On trapped rain water, after \code{if not height: return 0}, \tok{n} leads to prefix and suffix arrays and \tok{left} to two pointers. On valid anagram, after the length check, \tok{return} leads to sorting and \tok{count} to counting. Given the class of the located forking token, the remaining entropy of the algorithm, $H(A \mid \text{class})$, is 0.050 bits [95\% CI 0.014, 0.096], 0.153 and 0.189 bits on these three units, against the preregistered limit of 0.3. A blind locator with a frozen change-point rule recovered the same tokens on fresh paths, where the remaining entropy was at most 0.004 bits on the five Qwen3-8B and Gemma units (Table~\ref{tab:law}). The same structure appears in other tasks and families. Connected components in Qwen3-8B is settled at generated tokens 10 to 11, where a \tok{parent} or \code{def find} line leads to union find and \code{def dfs} to graph search, with 0 bits left at token 11.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-7/experiment-34}} Gemma's grid prompt forks at response index 32: \tok{visited} leads to DFS ($P(\text{BFS}) = 0.011$), and a newline, \code{if} or \tok{queue} to BFS (0.95 to 1.00). Shortest path has no single forking token within its first 60 tokens.

On the default tasks the forking token is decided by a wide margin. At the located forking position, the teacher-forced fork margin of the default is 7.46 nats on the grid task, 4.85 on shortest path, 17.04 on connected components and 6.10 on $k$-th smallest. Averaged over five prompt templates instead, the margins on the first three tasks are 6.33, 5.61 and 15.96 nats (Figure~\ref{fig:base}). Dividing these logits by 1.3 predicts at most 0.02 of samples off the default at $T = 1.3$, and 100 samples at $T = 1.3$ from the forking position produced no program off the default on any of the four tasks. A further 20 samples gave one program off the default on each of the grid and shortest path tasks. The temperature null of Section~\ref{sec:res-push} is what these margins predict: a temperature of 1.3 scales a 5 to 17 nat gap by $1/1.3$ and leaves the alternative out of reach.

The law was committed before any temperature sample and scored on 100 fresh shared streams per cell. It passed its unit criterion on five of six units: the three development units in Qwen3-8B (MAE 0.029, 0.054 and 0.043) and both held-out Gemma units (0.033 on substring search and 0.014 on first and last position). Lowering temperature from 1.0 to 0.3 removed the minority in one direction only on both Gemma units (10:0 and 13:0 discordant streams, McNemar $p = 0.001$ and $1.2\times10^{-4}$) and on minimum spanning tree weight (18:0, $p = 3.8\times10^{-6}$).

No held-out unit exceeded the disconfirming error of 0.2. The law is also not clearly better than simpler rivals. It has the lowest error on three of six units and beats the flat law on four of six (exact sign test $p = 0.34$). Bootstrap intervals of the difference, resampling streams, exclude 0 on minimum spanning tree weight [$-0.050$, $-0.025$], first and last position [$-0.081$, $-0.018$] and substring search [$-0.041$, $-0.002$]. On the grid task of Llama-3.1-8B every predictor fails. \subsection{What sets the forking token}
\label{sec:res-sets}

The task specification states carry the choice into the forking token (Table~\ref{tab:exchange}). Writing the task specification states of a prompt that names the minority algorithm into its padding twin produced that algorithm in 30 of 30 shared streams on all three mixed units, with every program passing. The padding twin alone gave 0 to 7 of 30, and a random exchange of matched norm 0 to 12 of 30. The argmax at the forking token flips with it (\tok{Kr} to \tok{Prim}), and the fork margin moves by 4.87 to 22.12 nats toward the minority, against at most 2.00 nats for the random exchange. The same exchange carries a prohibition. We wrote the task specification states of a shortest path prompt that bans Dijkstra, at all 36 blocks, into a neutral twin matched in token length, the same prohibition sentence with irrelevant nouns in place of the algorithm. The twin then wrote correct Bellman-Ford/SPFA in 21 of 30 streams; a post hoc McNemar test against a matched random exchange gives 21:0 ($p = 9.5\times10^{-7}$).\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-6/experiment-30}}

Post-training made the fork margins (Figure~\ref{fig:base}). On identical token ids formatted with the chat template, the fork margin of Qwen3-8B exceeds that of Qwen3-8B-Base by 3.27 nats on the grid task, 13.41 on connected components and 2.11 on shortest path, the three default tasks, and by 1.84 and 1.53 nats on the two mixed units. Without chat tokens the gains on the default tasks are 5.31, 11.05 and 2.69 nats, so the template does not produce them. At 64 ordinary phrasing positions per program the two models differ little: the next-token entropy of the base model is higher by 0.21 to 0.34 nats across the five tasks, and the token of the instruct model is the top token of the base model at 90.6\% to 95.3\% of phrasing positions on the default tasks. At the forking token, the choice of the instruct model is the second or third choice of the base model in 20, 17 and 19 of 20 programs. On the default tasks the Jensen--Shannon divergence between the two models is 7.3 to 12.0 times larger at the fork than at phrasing positions, but only 1.5 to 1.9 times larger than at phrasing positions matched for base-model entropy, which matches the known concentration of post-training shifts at high-entropy tokens~\citep{Meng2026}. The instruct default is therefore not the base model's average answer: on minimum spanning tree weight the base model's fork distribution, pushed through the instruct model's continuations, would give Prim 0.68 where the instruct model writes Kruskal 0.78.

Reading the choice before the forking token was not possible with the readouts we tried, which fits a decision made at that token. A natural language autoencoder on Qwen2.5-7B-Instruct~\citep{Yang2024} named the planned algorithm at the positions that end the prompt in 0 of 112 cases, although at the token that names the algorithm its explanations named it 80\% to 89\% of the time.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-6/experiment-32}} Sparse autoencoder features from Gemma Scope 2, the successor release of Gemma Scope~\citep{Lieberum2024}, read the log odds at the fork of Gemma across 120 prompt variants ($R^2 = 0.66$ against 0.18 for a text baseline), but a ridge readout of the raw residual reached 0.72. Clamping features also steered the fork less than a difference-in-means direction ($+1.78$ against $+4.04$ nats at matched norm). Distributed alignment search at the forking token produced edits that moved the algorithm, but controls with permuted labels and with randomly initialised networks kept 0.63 to 0.87 and 0.69 of the effect, so no certified variable of low rank for the algorithm was found.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-8/experiment-40}} Path patching located a stack of MLPs and attention heads at the forking position that carries the fork logit, but at the committed dose five matched random components flipped nearly as many programs as the top five (7:1 discordant streams on minimum spanning tree weight, two sided $p = 0.070$, and 0:1 on connected components).\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-8/experiment-41}} A logit-lens reading found no layer at which a ban vetoes the default at the token that first names the algorithm, because the choice is already made before it.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-2/experiment-8}} A community Jacobian lens failed its own gate against the logit lens on Qwen3-8B (top-1 agreement 0.104 against 0.291 at layer 27), so it was not used further.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-2/experiment-12}} Thought-anchor resampling of thinking traces~\citep{Bogdan2025} under a BFS ban showed DFS fixed from the first resampling point in 4 of 4 traces.

\subsection{Other controls reweight the same repertoire}
\label{sec:res-other}

Controls other than temperature moved programs among known algorithms when they moved them at all (Table~\ref{tab:controls}). In Table~\ref{tab:controls} a fixed push direction \emph{escapes} when, over its first 10 samples, the share of attempts off the default exceeds that of the unpushed prompt by at least 0.20 at a pass rate of at least 0.8 times the unpushed prompt's, with a confirmation at 30 samples by an exact binomial test. Random context seeds left the default intact: with \code{seed=d32qxk4nt43} or \code{seed=(horse chair roof love)} prepended, the grid task stayed BFS in 100 of 100 programs and shortest path Dijkstra in 100 of 100, although the word seed moved the residual state at the last prompt token 1.555 times as far as switching between paraphrases of the prompt does. Context with meaning did move the algorithm: a paragraph that implies a relaxation over all edges without naming it turned 61 of 92 correct shortest path programs into Bellman-Ford/SPFA (permutation $p < 0.001$). Instructions moved claims more than code. \code{Make a fully novel algorithm never seen before} lowered the Dijkstra share by 14.6 points, toward Bellman-Ford/SPFA. Under two 2,000-word novelty instructions, 84\% of outputs claimed a new algorithm, 39\% of those contained no code, and 75\% of the rest were catalogue algorithms.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-3/experiment-18}} On online bin packing, the shorter instruction \code{Make a new algorithm} still produced the textbook best-fit rule in 28 of 29 programs from Qwen3-14B and 28 of 28 from Qwen3-32B, both in thinking mode.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-10/experiment-54}} An audit of every correct program outside the catalogue from these early decoding conditions found none novel. Asking the model to list ten approaches and implementing one picked at random raised the number of ideas at depth 25 from 1.26 to 3.98 on the grid task and from 1.00 to 3.00 on shortest path, at pass rates of 0.55 and 0.75.

\subsection{Where a ban of five names lands in activation space}
\label{sec:res-geometry}

The one configuration that obeys the ban of five names moves to other known algorithms, among them unit weight Dijkstra (6 of its 17 correct survivors) and Bellman-Ford/SPFA (7), and whether unit weight Dijkstra lies at the edge of the banned algorithms or opposite them depends on how the map is built (Figure~\ref{fig:geometry}). Qwen3-32B with thinking writes BFS in 91 of 100 baseline programs; under the ban its six correct catalogue survivors are all unit weight Dijkstra, and on held-out ban templates 9 of 9 are. On a map of the ten grid algorithms built from forced prompts that name them (block 31), unit weight Dijkstra is the unbanned algorithm farthest from the banned five, with a geodesic distance, measured on a k-nearest-neighbour graph of the individual states with $k = 15$, of 1.63 times the median of the unbanned algorithms.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-9/experiment-46}} On a map built from name-scrubbed programs (block 33), that is, programs with every algorithm name removed, it lies at the edge, at 0.67 times the median and nearest to greedy best-first search. A later experiment that crossed six expansion disciplines with six containers (24 implementable cells, 287 name-scrubbed programs) found that this program map tracks the container more than the expansion discipline (partial Spearman 0.28 against 0.41 on Qwen3-32B and 0.23 against 0.30 on Qwen3-8B), so its edge placement is not yet a placement by mechanism; on that frame the Bellman-Ford/SPFA survivors land beside relaxation programs, and the covert BFS and DFS programs of configurations that disobey the ban land inside the banned classes (0.98 to 0.99).\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-10/experiment-55}} Distances on the map built from names track the lexical overlap of the algorithm names (Spearman $-0.61$ at $k = 15$) and the relation was not detected within algorithms in a test with aliases of the same algorithm (Spearman $-0.12$, $p = 0.46$; three algorithms, underpowered), so names and mechanisms are confounded there.\footnote{Code: \url{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-9/evaluation-8}} The landing evidence is weak at the level of algorithms: the permutation $p$ over algorithms is 0.20, its floor, and the opposite reading held in 10 of 15 robustness cells. The geometry is also correlational. Pushing Qwen3-8B's grid states inside the named map toward the survivor centroids produced BFS in 300 of 300 programs.

\section{Discussion}
\label{sec:discussion}

The headline contrast follows from where each control acts. The algorithm a code model writes behaves like an almost discrete decision taken at one or two tokens early in the program, and temperature acts on that decision only through the next-token distribution there; a push of the task specification states acts upstream, on the states that set that distribution (Section~\ref{sec:res-sets}). This single account explains the three regimes we observed. Where post-training has widened the fork margin to 4.85 to 17.04 nats, a temperature of 1.3 cannot reach the alternative, so the algorithm is fixed while every other position, where the next token is less certain, varies more. That is the phrasing growth of Figure~\ref{fig:phrasings}. Where the forking token is contested, temperature sharpens or flattens the same two or three known algorithms at the rate the forking-token logits predict. And where the model reaches the decision through many openings, as Llama does on the grid task, the choice is spread over the opening and no law at a single token captures it. In the terms of the question that motivates this work, a tight temperature with top-$k$ 10 gives one idea in a few phrasings, and a loose one gives the same idea, or the same few ideas, in more phrasings.

This account reconciles two findings that look contradictory. \citet{Lee2025} report that temperature above 1 raises algorithmic diversity among correct programs, and we find that temperature never changes the algorithm on default tasks. Both hold. On tasks whose fork is contested, temperature moves mass between known algorithms at the predicted rate; Prim on minimum spanning tree weight rises from 0.07 at $T = 0.3$ to 0.31 at $T = 1.3$. On tasks whose fork is decided by several nats, it does not. A diversity evaluation that pools tasks will see an average of the two. Our results also bear on the claim that a model returns the average answer and that only context moves it elsewhere. The instruct default is not the base model's average: post-training moved and sharpened one token, often promoting the base model's second or third choice, and left the repertoire unchanged.

For practice, the account says where to spend randomness. Temperature is a poor exploration control for algorithm choice, and on contested units its effect can be predicted before sampling from the forking-token logits. Inside program search, however, targeting the forking token was not reliably better than forcing a token at a random position (Section~\ref{sec:res-other}), so the account locates the decision without yet telling a search where to spend its randomness. Controls that act upstream of the fork, such as context that implies an algorithm, a prompt that lists approaches and then picks one, or perturbations of the task specification states, do change the algorithm, but they move it to the second choice the model already knows, and at a cost in correctness. The audits found no route from any control applied to single samples to a correct novel algorithm. An evaluator that keeps improvements across generations made the same 8B model better than the textbook rule on bin packing, which is where the field's discovery systems operate~\citep{RomeraParedes2023,Novikov2025}. Whether it made the model new remains open: one search's manual read found eight programs with a new idea, and the replication found none.

For interpretability, the results suggest that readouts of a plan taken before the code starts should be validated against the forking token. Natural language and sparse-feature readouts found no verbalised plan before the code, and fitted subspace edits at the fork moved the algorithm without passing the controls that would make them a variable of the model, consistent with the interpretability illusions that subspace patching can produce~\citep{Makelov2023}. The forking token is where intervention is cheap and measurable, but a certified mechanism for the choice is still missing.

\section{Limitations}
\label{sec:limitations}

The headline contrast between the push and temperature ran only in an 8-bit (W8A8) engine and was not rerun in bfloat16; the push alone changes the algorithm in bfloat16 at the same absolute push norm, but the paired contrast was not repeated, and it pools two tasks, with the grid task moving only 2.50 of 20 seeds. Most results come from one model, Qwen3-8B, in non-thinking mode. The composed law was tested on three held-out units in two other families; two passed and Llama's grid task failed, below the four held-out units the preregistered claim required, so the law's generality is an open question. The law was also not clearly better than the flat law, a baseline that predicts no change (four of six units, sign test $p = 0.34$), which means that much of its accuracy reflects how little temperature moves these units. The temperature null on shared seeds rests on 20 seeds per task, which bounds the change rate per seed below 0.17 per task, not at zero, and it ran with 8-bit linear layers; the bfloat16 fork margins and the grid sweep with independent samples agree with it, but the thinking-mode evidence is limited to shortest path and a 10-seed grid arm.

The tasks are short, well-known programming problems whose solutions are likely memorised, with catalogues of three to ten known algorithms; the conclusions may not hold for open-ended programs or for problems without a textbook solution. Experiments ran on different engines (bfloat16 and 8-bit linear layers, vLLM and Hugging Face); push escapes reproduced in bfloat16, but pushed cells showed precision sensitivity at the level of single streams. Phrasing clusters depend on a Jaccard threshold over AST shingles with normalised identifiers, and the growth was driven mostly by the grid task.

Labels and the novelty audit carry their own uncertainty. Labellers were gated per task, but the gate failed by its strict criteria for the decoding experiment with independent samples and for the agreement between runtime and AST labels on the path tasks ($\kappa = 0.753$), and the expansion-order tracer used for the ban of five names failed its gold gate, so those numbers are descriptive. In the program searches at most one LLM judge family passed its control gate, short of the two the bin packing rule required, so novelty there rests on manual reads, and the eight candidates of one search's reader, which the one gated judge also called new, were not reproduced by the replication. The geometry in activation space is correlational, and the map built from names is confounded by lexical overlap between algorithm names.

\section{Conclusion}
\label{sec:conclusion}

On the same random streams, a random push of Qwen3-8B's task specification states changed the algorithm in more seeds than temperature did, by 0.545 per seed (95\% CI 0.41 to 0.67) over shortest path and $k$-th smallest, a preregistered contrast that held in an 8-bit engine and is untested in bfloat16. Temperature from 0.3 to 1.3 left the default algorithm unchanged in all 60 seeds (20 per task) while phrasings multiplied, because a forking token, not temperature, chooses the algorithm. Fork margins of 4.85 to 17.04 nats on the default tasks, widened by post-training, account for the null, and on contested forks the forking-token logits committed before sampling predicted the temperature response within 0.014 to 0.054 total variation on five of six units. No control applied to single samples produced a correct algorithm outside the known repertoire; with an evaluator selecting across generations, one bin packing search yielded eight programs classed as a new idea, and its replication found none.

Future work follows directly:
\begin{itemize}
  \item testing the composed law on more held-out units and families, including models that reach the fork through many openings;
  \item extending the forking-token analysis to thinking traces, where the first approach named was fixed in every trace we read;
  \item testing, with more seeds and tasks, whether forcing branches at the forking token adds anything over forcing them at a random position inside program search, which our two bin packing searches and one TSP search left unsettled;
  \item searching for a variable of the algorithm choice that passes controls with permuted labels and with randomly initialised networks.
\end{itemize}
