\begin{center}
{\LARGE A single forking token fixes the algorithm a code model writes\par}
\end{center}
\vspace{0.5em}

\begin{abstract}
Instruction-tuned code models write the same algorithm for a task almost every time, and sampling temperature is the knob usually turned to change that. We locate where in generation the algorithm is chosen, labelling programs by execution and resampling continuations from every prefix, and compare knobs under shared random seeds. A single forking token fixes the algorithm. On the three tasks on which Qwen3-8B already writes two algorithms, the algorithm's entropy given the class of that token was at most 0.189 bits (bootstrap 95\% CI 0.123 to 0.239), down from 0.82 to 1.02 bits before it: a margin of $-0.111$ bits (95\% CI $-0.177$ to $-0.061$) below the 0.3-bit bar of a preregistered test that all three tasks passed. A blind relocation found such tokens on two held-out gemma-3-4b-it tasks, but not on Llama-3.1-8B-Instruct's grid task. Temperature acts only through that token's odds: where the default leads there by several nats, no temperature from 0.3 to 1.3 changed any seed's algorithm, whereas random perturbations of the prompt's task specification states, which set those odds, changed it in 55\% of seeds on two of those tasks, across one unperturbed and three perturbed runs (difference from temperature over seeds 0.545, 95\% CI 0.41 to 0.67; preregistered). Predicting the size of the temperature effect from the logits of that token succeeded on only one of the three tasks. No knob, instruction, ban or activation edit produced a new algorithm: sampling knobs rephrase a solution, but the idea is chosen at one token among options the model already holds.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Ask an instruction-tuned code model to implement a path search and it writes BFS, that is, breadth-first search; ask for a weighted shortest path and it writes Dijkstra's algorithm. Across six independent baselines, Qwen3-8B~\citep{Yang2025} wrote BFS in 1,199 of 1,200 programs for grid path search and Dijkstra in 1,174 of 1,200 programs for shortest path~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-1/experiment-1}{[code]}\,\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-1/experiment-6}{[code]}. It wrote one algorithm in at least 49 of 50 programs on each of 13 further tasks derived from LeetCode~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-2/experiment-11}{[code]}, and eight more open-weight configurations wrote BFS or DFS, that is, depth-first search, on the grid task~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-8/experiment-44}{[code]}. This is a code instance of generative monoculture~\citep{Wu2024}, also reported for other models~\citep{Narula2026,Lee2025}. It matters because the algorithm fixes a program's complexity and failure modes, and a model that always writes the textbook default cannot be asked for anything else by sampling it again.

The usual remedy is a knob: raise the sampling temperature~\citep{Peeperkorn2024}, truncate the distribution differently~\citep{Nguyen2024}, add randomness to the input~\citep{Nagarajan2025}, or forbid the techniques of earlier solutions~\citep{Lu2025}. Whether such knobs change the idea or only its wording is rarely measured, because diversity metrics score text or rely on a language-model judge~\citep{Lee2025} and independent samples confound a knob with sampling noise. Code permits a sharper test: running two programs decides whether they implement the same algorithm, and reusing the same random numbers in every condition holds the noise fixed~\citep{Ravfogel2024}.

Judging a knob also requires knowing where the choice is made. Resampling studies find forking tokens, positions at which resampling the continuation changes the outcome sharply~\citep{Bigelow2024}, and reinforcement learning acts mainly at a few such high-entropy positions~\citep{Wang2025,Meng2026}, but these studies concern answers to reasoning problems. Where a code model chooses the algorithm it implements has not been located.

We locate that choice token by token, labelling every program by execution and comparing knobs on identical noise. The algorithm is decided at a single forking token: temperature can only reweight the alternatives that token already weighs, while the internal states of the prompt's task specification set its odds. Our contributions are the following.

\begin{itemize}
\item \textbf{One forking token fixes the algorithm (Section~\ref{sec:res-fork}).} On the three mixed units, the Qwen3-8B tasks on which the model writes two algorithms, the algorithm's entropy given the class of one generated token is at most 0.189 bits (95\% CI 0.123 to 0.239), a margin of $-0.111$ bits (95\% CI $-0.177$ to $-0.061$) against a preregistered 0.3-bit bar that all three units passed. A blind relocation found such tokens on two held-out gemma-3-4b-it tasks, not on Llama-3.1-8B-Instruct's grid task.
\item \textbf{Temperature only reweights that token (Section~\ref{sec:res-temp}).} Where the default leads there by 4.85 to 7.46 nats, no temperature from 0.3 to 1.3 changed the algorithm of any of 20 seeds on three tasks, while phrasings multiplied; predicting the size of the temperature effect from the logits of that token worked on one of the three mixed units.
\item \textbf{The task specification states set its odds (Section~\ref{sec:res-states}).} Random perturbations of those states changed the algorithm in 55\% of seeds on two tasks, across one unperturbed and three perturbed runs (pooled difference from temperature over seeds 0.545, 95\% CI 0.41 to 0.67; preregistered), and patching in the states of a prompt that names the alternative wrote it on 30 of 30 seeds.
\item \textbf{Post-training widened the margin at that token (Section~\ref{sec:res-base})} by 2.11 to 13.41 nats over Qwen3-8B-Base on three collapsed units, on which the model writes one algorithm.
\item \textbf{No route produced a confirmed new algorithm (Sections~\ref{sec:res-prompts} and~\ref{sec:res-novel}).} Context seeds, novelty instructions and bans moved the choice only among known algorithms, and none of 45,892 audited correct programs was new; a program search with an evaluator gave eight programs one reader classed as new, which its replication did not reproduce.
\end{itemize}

\section{Related Work}
\label{sec:related}

\paragraph{Algorithmic diversity of code models.} Generative monoculture names the narrowing of output diversity relative to what a task admits, code included~\citep{Wu2024}. \citet{Lee2025} cluster correct solutions by algorithm with a language-model judge and find low algorithmic diversity that rises with temperature above 1 at a cost in correctness; prompt cues steer the choice~\citep{Narula2026}, denial prompting forbids earlier techniques~\citep{Lu2025}, and implementation priors explain why constraints against a default fail~\citep{Tang2026}. We label the mechanism a program executes and locate where the choice is made.

\paragraph{Creativity knobs.} Temperature correlates only weakly with novelty in stories~\citep{Peeperkorn2024}. Min-$p$ sampling~\citep{Nguyen2024}, dynamic temperature driven by entropy~\citep{Zhang2024} and adaptive temperature for code~\citep{Zhu2024} reshape the next-token distribution; seed-conditioning~\citep{Nagarajan2025}, intent factored generation~\citep{Ahmed2025} and PlanSearch~\citep{Wang2024} add randomness or plans before the answer; chat templates themselves collapse diversity~\citep{Yun2025}. We compare knobs on shared sampling noise, as Gumbel counterfactual generation does~\citep{Ravfogel2024}.

\paragraph{Forking tokens and post-training.} Forking Paths finds tokens at which the outcome distribution of resampled continuations changes abruptly~\citep{Bigelow2024}; hidden states anticipate such outcomes~\citep{Zur2025}, and high-entropy minority tokens~\citep{Wang2025} and thought anchors~\citep{Bogdan2025} carry the decisions of reasoning traces. Reinforcement learning mostly reweights choices the base model already considers~\citep{Meng2026}, most tokens of an aligned model are the base model's top token~\citep{Lin2023}, alignment can sit in a response's first tokens~\citep{Qi2024}, aligned models are less diverse than base models~\citep{Kirk2023,West2025} and concentrate probability on fewer continuations~\citep{Yang2025a}, and in code, self-distillation separates forks that need exploration from locks that need precision~\citep{Zhang2026}. We add which algorithm follows forks in code, and the post-training margin there.

\paragraph{Activation interventions and geometry.} Steering vectors~\citep{Rimsky2024} and single directions for refusal~\citep{Arditi2024} or truth~\citep{Marks2023} edit the residual stream, activation noise and steering raise output diversity~\citep{Khalid2026,Zhu2026}, and prompt states encode attributes of the coming response~\citep{Dong2025}. Distributed alignment search (DAS) fits causal subspaces of low rank~\citep{Geiger2023,Wu2023}, but subspace patching can act through pathways the model does not use~\citep{Makelov2023}, and expressive maps can align a network with algorithms it does not implement~\citep{Sutter2025}. Sparse autoencoders~\citep{Lieberum2024} often steer worse than simple baselines~\citep{Wu2025}; manifold steering follows fitted manifolds~\citep{Wurgaft2026} measured by geodesic distances~\citep{Tenenbaum2000}. We ask which site sets the forking token's odds.

\paragraph{Program search with an evaluator.} FunSearch~\citep{RomeraParedes2023}, Evolution of Heuristics~\citep{Liu2024}, ReEvo~\citep{Ye2024} and AlphaEvolve~\citep{Novikov2025} pair a language-model proposer with an executable evaluator, and many bin packing heuristics found this way reduce to simple parametric rules~\citep{Herrmann2026}. We ask only whether selection yields new heuristics from an 8B model.

\section{Method}
\label{sec:method}

\paragraph{Labelling programs.}
We call a task paired with a model a unit. Each task has a catalogue of three to ten known algorithms (Appendix~\ref{app:tasks}). A program is correct if it passes all of its task's hidden tests (40 to 48 per path task, 684 across the 13 bench tasks of Section~\ref{sec:setup}) in a sandbox with a time limit per test case. A runtime tracer of operations on data structures, grid reads, edge relaxations and recursion assigns the mechanism, rules over the abstract syntax tree assign a second label, and a blind language-model judge sees only programs on which the two disagree. The combined label agreed with adjudicated gold labels at Cohen's kappa 0.966 on the path tasks (Appendix~\ref{app:tasks}). A program matching no catalogue entry is labelled other and audited for novelty (below). A unit's default is the algorithm its model writes most often; a unit is mixed when the model writes two algorithms, each in a substantial share of programs, and collapsed when it writes one in nearly all of them.

\paragraph{Locating the forking token.}
Following Forking Paths~\citep{Bigelow2024}, prefix resampling keeps the first $j$ generated tokens (the prefix length) of programs the model sampled itself, for $j = 0, 4, 8, \ldots$, draws 8 continuations at temperature 1 from each prefix, labels them, and tracks the outcome distribution over algorithms. A Bayesian change-point model with a permutation null marks where the share of the sampled program's own algorithm jumps by at least 0.4, and 20 further continuations there and at control positions confirm it, because estimates from few samples are noisy~\citep{Bigelow2026}. We call the confirmed position the fork and the tokens before it the opening. At the fork we read the teacher-forced next-token distribution and group candidate tokens into classes by the algorithm that continuations forced to begin with them write. The entropy $H(A \mid C)$ of the algorithm $A$ given the class $C$ of the sampled forking token measures how much of the choice the token settles.

\paragraph{Predicting temperature's effect.}
The forking-token prediction at temperature $T$ composes the tempered probability of staying on the opening, the tempered distribution over forking tokens, and the algorithm each forking token leads to. It was committed by its hash before any sample at the target temperatures and is scored by the total variation distance between predicted and observed algorithm distributions, averaged over $T \in \{0.3, 0.7, 1.0, 1.3\}$, against a baseline that predicts no change (the $T = 1$ shares at every $T$), tempering of those shares themselves, and a variant placed at the position of highest entropy. On collapsed units we read the forking-token margin, the gap in log probability, in nats, between the token class of the default and the strongest alternative class.

\paragraph{Comparisons under shared seeds.}
Paired comparisons use common random numbers: each sample slot, which we call a seed, owns one stream of uniform random numbers, and the sampler maps the tempered next-token distribution to a token by inverse-CDF lookup, so two programs from one seed differ only by the condition. We count the seeds whose algorithm differs across a set of conditions, compare paired outcomes by exact McNemar tests on discordant seeds~\citep{Mcnemar1947}, and test contrasts over seeds by sign flips.

\paragraph{Perturbing and patching task specification states.}
A prompt has a condition sentence (empty, neutral or a ban, a negative constraint naming algorithms not to use), a task specification (problem statement and function signature) and a read position, its last token; we call the residual stream states at the tokens of the task specification its task specification states. Each ban has a neutral twin of identical token length in which irrelevant nouns replace the algorithm names. We call the following intervention a random push: it writes a random unit direction $u$ into the residual stream during the prompt pass only. At block $l$ and position $i$ of the task specification, the component along $u$, measured from the neutral twin's state, is set to $\alpha\, n_{l,i}$, where $n_{l,i}$ is the norm of the displacement that the ban sentence itself produces there. One ban unit ($\alpha = 1$) is thus a random displacement of the size that a ban of one sentence causes; unless stated, it is applied at blocks 12 to 23. Activation patching replaces the task specification states of a prompt, at every block, with those of another prompt of the same length, for example \texttt{Implement Prim's algorithm} patched into a padding twin whose instruction tokens are filler; a random replacement of matched norm is the control.

\paragraph{Diversity and novelty.}
Diversity is the Hill number of correct programs, that is, the Hill number of order 1~\citep{Hill1973}, the exponential of the Shannon entropy, of the algorithm labels of correct programs, rarefied to subsamples of 25. Phrasings are clusters of programs whose AST 4-gram shingles, after identifiers are normalised, reach a Jaccard similarity of 0.8. A correct program labelled other counts as novel only if, after stress tests, a comparison with its nearest known solutions by tree edit distance~\citep{Zhang1989}, two blind judges gated on known control programs and a full manual read, it implements no known algorithm; with none among $n$ programs, the rule of three bounds the rate by $3/n$.

\section{Experimental Setup}
\label{sec:setup}

\paragraph{Models.} The main model is Qwen3-8B~\citep{Yang2025} in non-thinking mode at temperature 1, in bfloat16 with exact common random numbers, and in some experiments in a W8A8 engine, with 8-bit floating-point weights and activations, on smaller GPUs; the perturbation results hold in bfloat16 (Appendix~\ref{app:controls}). Qwen3-8B-Base serves for the base comparison, and gemma-3-4b-it, gemma-3-4b-pt~\citep{Team2025} and Llama-3.1-8B-Instruct~\citep{Grattafiori2024} as further families. The ban screen adds Qwen3-14B and Qwen3-32B in thinking and non-thinking mode, gemma-3-27b-it and Qwen2.5-Coder-32B-Instruct (\url{https://huggingface.co/Qwen/Qwen2.5-Coder-32B-Instruct}).

\paragraph{Tasks.} The two path search tasks follow a public set of creativity probes for code models (\url{https://github.com/DrejcPesjak/llm-creativity}): grid path search with moves to the four neighbouring cells, where any valid path is accepted so BFS is not forced, and weighted shortest path between one pair of nodes on a directed graph. Thirteen bench tasks derived from LeetCode problems~\citep{Xia2025}, such as $k$-th smallest element, two sum and connected components, carry 684 hidden test cases and references for 54 algorithms. Sixteen further units, among them minimum spanning tree weight, trapped rain water and valid anagram, were built the same way~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-5/experiment-25}{[code]}\,\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-5/experiment-26}{[code]}. Each task has five prompt templates. Appendix~\ref{app:search} describes the online bin packing and TSP tasks of the program search.

\paragraph{Preregistration and audits.} Every decisive rule and prediction was committed by its hash, in a SHA-256 chain, before the samples it governs, every headline number was recomputed from raw rows by an independent script, and placebo versions of each test were checked to fail. Shares carry Clopper-Pearson~\citep{Clopper1934} or Wilson~\citep{Wilson1927} intervals, contrasts bootstrap intervals. Each experiment fits on one GPU, such as an RTX 4090 or an RTX 2000 Ada, in about 1 to 3 hours of GPU time, with vLLM~\citep{Kwon2023} for unpaired sampling. Code, prompts, raw generations, labels and the scripts that recompute each number are in the paper's repository~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC}{[code]} and linked at each claim.

\section{Results}
\label{sec:results}

\subsection{One forking token fixes the algorithm}
\label{sec:res-fork}

On the three mixed units of Qwen3-8B, sampled programs share an opening of 18 to 61 tokens, and the next token settles the algorithm (Figure~\ref{fig:resampling}, Table~\ref{tab:forks}): the share of continuations writing the default stays between 0.47 and 0.96 along the opening and jumps to 1 or 0 at the forking token. The preregistered test required the entropy of the algorithm given the class of the forking token to be at most 0.3 bits on at least two units. It passed on all three: 0.050 bits (bootstrap 95\% CI 0.014 to 0.096) on minimum spanning tree weight, 0.153 (0.091 to 0.203) on trapped rain water and 0.189 (0.123 to 0.239) on valid anagram, against 0.82, 0.97 and 1.02 bits at the fork before the token is sampled. On the least decisive unit the margin to the bar is $-0.111$ bits (95\% CI $-0.177$ to $-0.061$)~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-7/experiment-35}{[code]}. On minimum spanning tree weight the opening ends with a comment marker; the next token is \stok{Kr} with probability 0.72, after which every continuation writes Kruskal's algorithm, or \stok{Prim} with probability 0.27, after which 97\% write Prim's (\textvisiblespace\ marks a leading space).

A blind locator on fresh samples recovered the forks of minimum spanning tree weight and trapped rain water and, on valid anagram, the next decision inside the counting branch (at most 0.004 bits), and found single forking tokens on two held-out gemma-3-4b-it tasks (0.001 bits each)~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-8/experiment-43}{[code]}, and Gemma's grid task forks the same way (Table~\ref{tab:forks})~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-6/experiment-31}{[code]}. Collapsed units have forks too, which surface in perturbed and banned samples (Appendix~\ref{app:tasks}).

The fork is not universal. On Llama-3.1-8B-Instruct's grid task the openings that reach a forking token cover about 2\% of programs, and the algorithm keeps 0.63 bits given the located decisions; on weighted shortest path, perturbed generations stay undecided for at least 60 tokens, and on $k$-th smallest the algorithm is fixed before the first generated token. Where a fork exists it is a high-entropy position (Appendix~\ref{app:tasks}).

\subsection{Temperature only reweights the forking token}
\label{sec:res-temp}

If one token decides, temperature can act on the algorithm only through that token's distribution and the probability of reaching it. Figure~\ref{fig:temperature} compares the forking-token prediction, committed before sampling, with the observed share of the minority algorithm at four temperatures on shared token streams. Lowering the temperature from 1.0 to 0.3 removed the minority algorithm in paired seeds as predicted: all 18 discordant seeds moved to the default on minimum spanning tree weight (exact McNemar $p = 3.8\times10^{-6}$), as did all 10 on Gemma's substring search and all 13 on its first and last position.

The prediction's mean total variation distance from the observed shares (F in Figure~\ref{fig:temperature}) was 0.014 to 0.054 on five of six units, under the preregistered bar of 0.10, and 0.142 on Llama's grid task, whose many openings it does not model. Predicting no change (B) was almost as good: the forking-token prediction beat it on only 4 of 6 units (exact sign test $p = 0.34$), though it beat tempering of the shares themselves and the variant at the position of highest entropy on 5 of 6. A simpler prediction from the forking token alone, committed before sampling on the three mixed units, matched the observed response only on minimum spanning tree weight, one unit against the two its test required. The forking token explains the direction and mechanism of temperature's effect, but not yet its size.

On collapsed units the forking-token margin puts the alternative out of reach. On the neutral twin prompt the default leads the strongest alternative by 7.46 nats on grid path search, 4.85 on shortest path, 17.04 on connected components and 6.10 on $k$-th smallest. At $T = 1.3$ these margins imply rates of leaving the default of 0.002, 0.020, below 0.0001 and 0.009, and 100 continuations from each fork at $T = 1.3$ gave none. At a fixed seed, then, tight temperature with top-$k$ 10 yields about one idea in a few phrasings; top-$k$ 10 even gave programs identical token for token to top-$p$ 1 in 600 of 600 pairs that share a seed, since every forking token lies in the top ten. At $T = 0.3$, ten trajectories on minimum spanning tree weight were nine Kruskal programs in three phrasing clusters and one Prim program. Loosening the temperature moves mass to the second idea the forking token already weighs and multiplies phrasings (Kruskal from 4 to 22 clusters per 100-program cell between $T = 0.3$ and 1.3, Prim from 2 to 7); no third algorithm appeared.

\subsection{The task specification states set the forking token's odds}
\label{sec:res-states}

Two measurements locate what sets the forking token's distribution. The first is activation patching. Patching the task specification states of a prompt that names the minority algorithm into its padding twin wrote the minority on 30 of 30 seeds on all three mixed units, every patched program correct, against 7, 4 and 0 of 30 for the padding twin and 12, 4 and 0 for a random replacement of matched norm. It moved the teacher-forced forking-token margin by $-4.9$, $-5.5$ and $-22.1$ nats, against $-1.2$, $-2.0$ and $+0.3$ for the replacement~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-7/experiment-35}{[code]}. Patching the states of a ban of Dijkstra's algorithm into its neutral twin moved 24 of 30 seeds to Bellman-Ford or SPFA (21 correct; McNemar 24:0), whereas patching the read position transferred nothing on any of six tasks~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-6/experiment-30}{[code]}. On two sum and find the duplicate the ban is carried instead by the condition sentence: patching its states transferred the ban on 30 and 27 of 30 seeds, patching the task specification states on 13 and 1.

The second is the random push, whose effect depends on its site. Figure~\ref{fig:sites} counts the correct programs off the default after the same random push, at the same dose per position, is written into six sites~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-4/experiment-20}{[code]}. At the read position and on the condition sentence it changed the algorithm of none of 526 and 527 correct programs, and at the task specification's late blocks (24 to 35) of only 6 of 521. Yet a push at the read position displaces the final state as much as a push at the task specification (median norm 141 against 159), and at matched displacement the task specification keeps an advantage in log odds of 2.15 (95\% CI 1.79 to 2.51). Pushes on the first 32 generated tokens, where the forks lie, also worked. The effects reappear in bfloat16 (Appendix~\ref{app:controls}).

The perturbation reaches only known alternatives, and only on some tasks. With 40 fresh directions per task (8 on nine bench tasks), two ban units changed the algorithm on $k$-th smallest (63\% of directions; quickselect or a size-$k$ heap), connected components (73\%; DFS or BFS), shortest path (20\%; Bellman-Ford or SPFA), two sum (13\%; brute force) and grid path (13\%; DFS), and on none of the other ten tasks~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-4/experiment-22}{[code]}. No subspace we fitted predicts which directions work (Appendix~\ref{app:controls}), and cheaper knobs that act on the text reach as high a Hill number of correct programs (Appendix~\ref{app:knobs}).

\subsection{Post-training widened the margin at the forking token}
\label{sec:res-base}

Is the default the base model's average answer? We scored identical token ids, formatted with the chat template, under Qwen3-8B and Qwen3-8B-Base (Appendix~\ref{app:base}). At the forking tokens of the three collapsed units the instruct margin exceeds the base margin by 3.27 nats on grid path search, 13.41 on connected components and 2.11 on shortest path, while the entropy at phrasing positions, which change only the wording, differs by only 0.23 to 0.31 nats, as preregistered~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-8/experiment-43}{[code]}. The default is a sharpened choice, not the base model's mean: the base model already prefers it at the fork, by 2.55 to 3.50 nats. On minimum spanning tree weight post-training even reversed the preference: pushed through the instruct model's algorithm for each token, the base model's forking-token distribution implies Prim with probability 0.68, where the instruct model writes Kruskal in 78\% of programs; Gemma's grid task shows a similar reversal~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-9/experiment-50}{[code]}. Part of this concentration reflects base-model uncertainty at the fork (Appendix~\ref{app:base})~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-10/experiment-56}{[code]}.

\subsection{Prompts move the choice among known algorithms}
\label{sec:res-prompts}

\paragraph{Context seeds and instructions.} Prepending a context seed, random words (\texttt{seed=(horse chair roof love)}) or a random string (\texttt{seed=d32qxk4nt43}), shifted the modal algorithm by at most one percentage point on both path tasks (90\% intervals within $\pm$15 points). The two long novelty instructions (\texttt{Make a fully novel algorithm never seen before}, with a 2,000-word rationale) made 84\% of 574 outputs claim a new algorithm. Yet 39\% of those contained no code, 75\% of the rest implemented catalogue algorithms, and none of the 23 correct programs outside the catalogue was new. The instructions spread the choice over known algorithms (Hill numbers of correct programs 1.8 to 4.5 without thinking) at a cost in pass rate~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-3/experiment-18}{[code]}. On bin packing, \texttt{Make a new algorithm} returned best fit in 28 of 29 and 28 of 28 programs of Qwen3-14B and Qwen3-32B in thinking mode~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-10/experiment-54}{[code]}.

\paragraph{Bans.} A ban of the default is mostly obeyed and lands on one known substitute: DFS on the grid task (86 of 100) and Bellman-Ford or SPFA on shortest path (83 of 100)~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-2/experiment-9}{[code]}; on the bench tasks it acts where the forking tokens surface (Appendix~\ref{app:knobs}). A ban of the five grid algorithms used most is answered differently: Qwen3-8B avoided none of them and reimplemented them without their names in 41\% of programs. Across ten configurations of open-weight models, lexical compliance (no banned name in the program) exceeded mechanistic compliance (a search mechanism outside the banned set) by 0.70 (95\% CI 0.57 to 0.82), positive in all ten (descriptive; a second instrument missed its agreement threshold)~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-9/experiment-45}{[code]}. Only Qwen3-32B in thinking mode obeyed often enough to clear the preregistered bar of 0.20 (17 of 50 correct survivors, programs that pass and leave the banned set; Table~\ref{tab:fivename}).

\paragraph{Edge or opposite.} Figure~\ref{fig:geometry} places Qwen3-32B's baseline and ban prompts among the task specification states of forced prompts for ten grid algorithms. Along the first principal component the ban moves the prompt states from the BFS and DFS end toward the middle of the banned set, not toward Dijkstra with unit weights, which we name UW-Dijkstra as in the figure, although every catalogue survivor of the obeying model is Dijkstra with unit weights (6 of 6; 9 of 9 on held-out templates). Whether that survivor lies at the edge of the banned five or opposite them depends on the map. On an Isomap graph~\citep{Tenenbaum2000}, classical multidimensional scaling of geodesic distances, its geodesic distance from the banned five is 1.63 times the median of the algorithms outside the banned set on a manifold built from prompts that name the algorithm (opposite) but 0.67 on one built from programs with the names removed (edge; Appendix~\ref{app:maps})~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-9/experiment-46}{[code]}. The geometry is correlational: pushing prompt states toward the survivors' centroids produced BFS in all 300 programs, and no manifold showed a ring.

\subsection{No route produced a confirmed new algorithm}
\label{sec:res-novel}

In the nine experiments whose audits cover all of their correct programs, none of 45,892 correct programs implemented a new algorithm (bound by the rule of three 0.007\% per program); the 39 correct programs labelled other were labeller misses, catalogue variants or degenerate (Table~\ref{tab:novelty} in Appendix~\ref{app:novelty}). Forcing each of the forking token's top 64 candidates reached only one more known algorithm on each of three units, about 2 to 50 million samples away at $T = 1$. An evaluator helps only in part: with selection, an island-model search with Qwen3-8B as mutator beat best fit on held-out bin packing instances (1.40\% to 2.42\% excess bins on a Weibull test set, against 3.98\%), and an independent implementation reproduced the gain for three of five arms~\href{https://github.com/ai-inventor-papers/ai-invention-295f8e-prompt-bans-substitute-not-just-subtract/tree/fork/run_jSassd-YWLVC/round-10/experiment-52}{[code]}. None beat the strongest published heuristics. One reader classed eight programs of the first search, all preferring a leftover that is a whole multiple of the item size, as a new idea, but only one of three judge families passed its control gate, short of the preregistered two, and the replication found none of its 40 audited candidates new (Appendix~\ref{app:search}).

\section{Discussion and Limitations}
\label{sec:discussion}

One forking token accounts for these results. Decoding knobs act on its distribution and cannot cross a wide margin; prompts that name an alternative, and on the path tasks bans, act on the task specification states that set its odds; and post-training wrote the default as a wide margin at this token. Read this way, a code model's creativity in choosing an algorithm is the entropy of one token over a few known options, and every knob we tested only moves mass among them. The data reject the view that the model returns the mean of its possible answers and that only context moves it elsewhere: the default is a sharpened, sometimes reversed, base-model choice, and context moved the algorithm only by changing the states that set the token's odds. Consistent with \citet{Lee2025}, temperature above 1 raised the Hill number of correct programs modestly on mixed units, not on collapsed ones (Appendix~\ref{app:knobs}).

For practice, this suggests acting on the forking token's inputs rather than on global temperature; for evaluation, it argues for labels assigned by execution and for designs with shared seeds, without which rewritten code looks like a new idea. Internal readouts locate the decision but certify no variable for it (Appendix~\ref{app:readouts}), as \citet{Makelov2023} and \citet{Sutter2025} warn.

\subsection{Limitations}
\label{sec:limitations}

The main model is Qwen3-8B in non-thinking mode. Forking tokens were confirmed in gemma-3-4b-it but not in Llama-3.1-8B-Instruct, whose grid choice is reached through many openings, and the account does not cover every task: shortest path decides late and $k$-th smallest before generation. Forks can be located by resampling only where the model already writes two algorithms; on collapsed units they were found in perturbed or banned samples, with margins from teacher forcing. The forking-token prediction of temperature's effect is not established as better than predicting no change, and only three held-out units were scored, one fewer than preregistered.

The preregistered contrast with shared seeds ran in a W8A8 engine on two tasks that an earlier screening experiment had selected because random pushes moved them; it was not rerun in bfloat16, although effects under 40 other directions reproduced there, and the perturbation moves the algorithm on only 5 of 15 tasks. The tasks are well-known problems with small catalogues of textbook algorithms the models have likely memorised, so open-ended design problems may behave differently. Two instruments missed their preset agreement thresholds, so the results for context seeds and the compliance values are descriptive. The novelty audits rest on catalogue labels for most programs and on one reader's manual reads for disputed ones, judge agreement was often low, and the program searches used at most 2,000 calls per arm and seed, far fewer than published discovery systems. The internal handles are not specific variables, and the geometry of Section~\ref{sec:res-prompts} is correlational.

\section{Conclusion}
\label{sec:conclusion}

Where it could be located, the algorithm an open-weight code model writes was chosen at one sampled token, among options the model already holds. That explains why temperature rephrases code without changing its algorithm on collapsed units, while prompt cues and edits of the task specification states can change it. Making a model creative in this sense means placing a new option at that token, which no knob we tested did. Future work should test the account on more model families and on tasks without a textbook catalogue, predict the size of temperature's effect from openings summed over many paths, and give program-search operators that act on the forking token's inputs.
