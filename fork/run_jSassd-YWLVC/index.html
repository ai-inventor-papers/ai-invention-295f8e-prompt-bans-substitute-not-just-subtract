A Random Activation Push Changes a Code Model's Algorithm Where Temperature Does Not

TL;DR

Sampling temperature is often treated as the creativity control of a language model. This paper asks whether it changes which algorithm a code model implements, or only how the model writes the same one. With the random draws held fixed per seed, temperature from 0.3 to 1.3 never changed the algorithm Qwen3-8B wrote, in 20 seeds on each of three tasks, while the number of phrasings grew. A random push to the model's internal states at the prompt tokens that state the task did change it, in more seeds than temperature did: a paired difference of 0.545 per seed (95% CI 0.41 to 0.67), pooled over shortest path and k-th smallest. The algorithm is settled at one or two forking tokens early in the program, where the default leads by several nats, more than this temperature range can overcome.

Contributions

  1. A task-state push changes the algorithm where temperature does not

    On the same random streams, a random push to the task specification states changed the algorithm in more seeds than temperature did, by 0.545 per seed (95% CI 0.41 to 0.67) over shortest path and k-th smallest. Temperature from 0.3 to 1.3 changed it in 0 of 20 seeds on each of three tasks, while phrasing clusters on the grid task rose from 3 to 13.

  2. One or two forking tokens settle the algorithm

    Given the class of the forking token, at most 0.19 bits of uncertainty about the algorithm remain. On four default tasks the default leads at that token by a fork margin of 4.85 to 17.04 nats.

  3. A law built from that token's logits predicts temperature's effect

    Committed before sampling, it matched the observed algorithm mix across four temperatures within a mean total variation distance of 0.014 to 0.054 on five of six units, two of them held-out Gemma-3-4B units. It failed on Llama-3.1-8B's grid task (0.142), and a baseline that predicts no change was close.

  4. Task states and post-training set the fork

    Writing the task specification states of a prompt that names the minority algorithm into an aligned copy without that instruction produced the minority algorithm in 30 of 30 samples on each of three tasks. On the three default tasks, post-training widened fork margins by 2.11 to 13.41 nats while changing entropy at phrasing positions by less than 0.5 nats.

  5. Other controls reweight the same repertoire

    Random seeds, novelty instructions, bans, activation pushes and program search moved programs among known algorithms. No audit of a control applied to single samples found a correct novel algorithm; eight bin-packing programs from one evaluator-guided search were classed as a new idea, and a replication found none. Where a ban of five names lands in activation space depends on whether the map is built from names or from programs.

Method

The method has one aim: to tell a change of algorithm apart from a change of wording, and to find the token at which the algorithm is chosen.

What goes in

Coding prompts whose possible answers are known in advance. The study starts from two path search tasks. In the grid task, solve(grid, start, goal) returns a valid path on a grid with walls; its catalogue holds breadth-first search (BFS), depth-first search (DFS), bidirectional BFS, iterative deepening DFS, A* and unit weight Dijkstra. The weighted shortest path task works on a directed graph, with a catalogue of Dijkstra, Bellman-Ford with its queue variant SPFA, bidirectional Dijkstra, Floyd-Warshall and Dial's algorithm. Each has 40 to 48 seeded hidden test cases with a time limit per case, and reference implementations of every catalogue algorithm that pass all tests.code: Where an algorithm ban sends an AI coder A further 13 tasks, the bench, were derived from LeetCode problems with frozen wording and catalogues of 3 to 6 algorithms each, 684 hidden test cases in total, and references for all 54 catalogue algorithms.code: Coding-task bench with a baseline pilot

The main model is Qwen3-8B, in non-thinking mode unless stated, with Qwen3-8B-Base for the post-training comparison. Held-out units come from Gemma-3-4B and Llama-3.1-8B, and Qwen3-14B and Qwen3-32B with thinking enter the ban experiments. A unit is a task paired with one model. It is a default task when the instruct model writes one algorithm in essentially all samples, and a mixed unit when its unperturbed samples already contain a second algorithm at a share of roughly 0.1 to 0.4.

What happens to it

  1. Each program is labelled by what it does when run. A sandboxed runtime tracer records queue, stack and heap operations, edge relaxations and grid reads; it is combined with AST rules, and a blind LLM judge breaks disagreements. On the bench tasks the runtime and AST labellers agreed at Cohen's κ 0.84 to 1.00. On the path tasks the combined label agreed with an adjudicated gold label at κ = 0.966, with 22 of 22 references correct, though the stricter criterion of that gate (κ = 0.753 between the runtime and AST labellers) was not met. A program is correct when it passes every hidden test.

  2. Ideas are counted apart from phrasings. The runtime label of a correct program is its idea. Within one idea, programs whose AST 4-gram shingle sets, with identifiers normalised, have Jaccard similarity of at least 0.8 form one phrasing cluster; 0.7 and 0.9 serve as sensitivity values. Diversity over ideas is the Hill number of order 1 (Hill-1) among correct programs.

  3. Conditions share one random stream per seed. Each seed owns one stream of uniform variates, and every condition maps the same variates through its own next-token distribution, so a difference on one seed is caused by the condition, not by a different draw. A task's change count is the number of seeds whose algorithm label differs anywhere across a block of conditions. The temperature block ran 20 seeds per task, spread over five prompt templates, at T = 0.3, 0.7, 1.0 and 1.3 with top-p 1, plus top-k 10 at T = 0.7 and min-p 0.1 at T = 2.0 as sensitivity conditions.code: Same seed: temperature vs plan nudges

  4. A random push enters at the task states. One isotropic unit direction is added, during the prefill only, to the residual stream activations at the prompt tokens that state the task (the task specification states) in blocks 12 to 23. Its size is a multiple α of the displacement that a ban prompt induces at the same positions. Six fixed directions were run at α = 1 and 2.

  5. Prefix resampling finds the forking token. Following Forking Paths analysis, base programs are resampled from their prefixes at increasing lengths, every continuation is labelled, and a preregistered Bayesian change-point rule, calibrated against permutation nulls, detects where the algorithm distribution shifts. The change point is refined to a single token and confirmed by forcing each candidate. The fork margin is the teacher-forced gap in log probability, at that token, between the class of tokens that lead to the default algorithm and the best class that leads elsewhere.

  6. A law composed at the fork predicts temperature. It tempers the probability of each shared opening and of each token at the fork, and mixes the algorithm shares that follow each token at T = 1:

    PT(A) = ∑c wT(Oc) [ ∑t πT(t | Oc) G(t, A) + rT(c) P(A | restc) ] + (1 − ∑c wT(Oc)) qrest(A)

    Oc, wT(Oc)
    the c-th shared opening before a forking token, and the probability of sampling it at temperature T: the product of tempered teacher-forced token probabilities along it
    πT(t | Oc)
    the tempered next-token distribution at the fork, renormalised over the top 10 logits for top-k 10
    G(t, A)
    P(A | t), the share of algorithm A among T = 1 continuations forced from token t, or the same mixture over a second fork's tokens when t opens one
    rT(c), qrest
    the tempered mass outside the top 20 tokens, and the composition of samples that leave the located openings

    The prediction is averaged over five prompt templates and uses only teacher-forced logits and T = 1 conditionals, so it can be committed before any temperature sample is drawn.code: Predicting how temperature shifts code ideas Four rivals were committed with it: a flat law that keeps the T = 1 shares at every temperature; share tempering, which raises the T = 1 shares to the power 1/T and renormalises; a single fork law without the second level; and the same law at the position of highest entropy. Each is scored by its mean absolute error (MAE), the mean over the four temperatures of the total variation distance between predicted and observed label distributions.

  7. Exchanges of internal states ask what sets the fork. A task-state exchange pairs a forced prompt (Implement the task with ⟨minority algorithm⟩) with a padding twin whose instruction is replaced by padding tokens, so that all positions align. The task specification states of the forced prompt are written into the forward pass of the twin, which then samples on shared streams, against a random exchange matched in norm.code: Where temperature changes the algorithm an LLM writes Separately, Qwen3-8B and Qwen3-8B-Base are teacher-forced on identical token ids, formatted with the chat template, at the forking tokens and at 64 phrasing positions of 20 programs per task.

  8. Other controls and a novelty audit bound the result. Random context seeds (seed=d32qxk4nt43 and seed=(horse chair roof love) prepended to the prompt), a semantic seed that implies an algorithm without naming it, instructions from be creative to a 2,000-word request for a fully novel algorithm, bans of one or of five algorithm names, and an island-model program search in the manner of FunSearch. Every correct program labelled outside its task's catalogue was compared with a corpus of about 18,000 known solutions, read by blind LLM judges gated on known controls, and read manually.

What comes out

  • For each block of conditions, the change count per task, with its rate bounded by a Clopper-Pearson interval.
  • Phrasing clusters per idea, and the number of ideas at depth 25: the expected count of distinct ideas among 25 correct programs drawn from a cell.
  • The forking token of each unit, its fork margin in nats, and H(A | class), the entropy of the algorithm given the class of the forking token.
  • A committed prediction of the algorithm mix at each temperature, scored on 100 fresh shared streams per cell.
  • A count of correct novel algorithms, reported with the rule-of-three bound 3/n when it is zero.

Why it is built this way

Counting distinct outputs cannot answer the question. Two programs can differ in every line and implement the same algorithm, and a program can name one algorithm while executing another, so labels come from what the code does when run. Comparisons across temperatures drawn with independent random numbers mix the effect of temperature with sampling noise: with a default share near 1.0, a few stray samples look like a temperature effect. Knowing that an algorithm changes also says nothing about where the decision was made. Prefix resampling answers that.

Every decisive prediction, threshold and analysis rule was written to a SHA-256 hash chain before the samples it governs were drawn. Every headline number was rederived from raw rows by an independent script sharing no code with the analysis, and placebo versions of each test were run and rejected at about their nominal rate.

What T = 1.3 can overcome. Dividing these logits by 1.3 predicts at most 0.02 of samples off the default, and 100 samples at T = 1.3 from the forking position produced no program off the default on any of the four tasks.

On every unit where the instruct model writes two algorithms, prefix resampling places the decision at a single token after a shared opening. On minimum spanning tree weight the 61-token opening is followed by the word after the comment marker #: Kr (probability 0.72) leads to Kruskal in every continuation, and Prim (0.27) to Prim in 97%. On trapped rain water, after if not height: return 0, n leads to prefix and suffix arrays and left to two pointers. On valid anagram, after the length check, return leads to sorting and count to counting.

The preregistered claim is graded partial. Five of six scored units pass (0.83, above the 0.70 bar), but only three held-out units were scored where the claim required four, so the held-out criterion is underpowered rather than met. No held-out unit exceeded the disconfirming error of 0.2. Bootstrap intervals of the difference from the flat law exclude 0 on minimum spanning tree weight [−0.050, −0.025], first and last position [−0.081, −0.018] and substring search [−0.041, −0.002]. On first and last position the first forking token is impure, and the second level found inside it lowers the error from 0.051 for the single fork law to 0.014.

Lowering temperature from 1.0 to 0.3 removed the minority in one direction only on both Gemma units (10:0 and 13:0 discordant streams, McNemar p = 0.001 and 1.2 × 10−4) and on minimum spanning tree weight (18:0, p = 3.8 × 10−6). On the grid task of Llama-3.1-8B every predictor fails. The task specification states and post-training set the fork

Measured on
Qwen3-8B in bfloat16, 30 shared streams per arm, on minimum spanning tree weight (Prim), trapped rain water (two pointers) and valid anagram (fixed count array).
Compared against
The padding twin alone, which gave 0 to 7 of 30, and a random exchange of matched norm, 0 to 12 of 30. The fork margin moved 4.87 to 22.12 nats toward the minority, against at most 2.00 nats for the random exchange.

The argmax at the forking token flips with the exchange (Kr to Prim). The same exchange carries a prohibition. Writing the task specification states of a shortest path prompt that bans Dijkstra, at all 36 blocks, into a neutral twin matched in token length made the twin write correct Bellman-Ford/SPFA in 21 of 30 streams; a post hoc McNemar test against a matched random exchange gives 21:0 (p = 9.5 × 10−7).code: Where a coding model decides its algorithm

Post-training made the fork margins. On identical token ids formatted with the chat template, the fork margin of Qwen3-8B exceeds that of Qwen3-8B-Base by 3.27 nats on the grid task, 13.41 on connected components and 2.11 on shortest path, and by 1.84 and 1.53 nats on the two mixed units. Without chat tokens the gains on the default tasks are 5.31, 11.05 and 2.69 nats, so the template does not produce them. At 64 ordinary phrasing positions per program the two models differ little: the base model's next-token entropy is higher by 0.21 to 0.34 nats, and the instruct model's token is the base model's top token at 90.6% to 95.3% of phrasing positions on the default tasks.

At the forking token, the instruct model's choice is the base model's second or third choice in 20, 17 and 19 of 20 programs. On the default tasks the Jensen–Shannon divergence between the two models is 7.3 to 12.0 times larger at the fork than at phrasing positions, but only 1.5 to 1.9 times larger than at phrasing positions matched for base-model entropy. The instruct default is therefore not the base model's average answer: on minimum spanning tree weight the base model's fork distribution, pushed through the instruct model's continuations, would give Prim 0.68 where the instruct model writes Kruskal 0.78.

What this says about temperature as a creativity knob

One account covers the three regimes the paper observed. The algorithm behaves like an almost discrete decision taken at one or two tokens early in the program, and temperature reaches it only through the next-token distribution there. Where post-training has widened the fork margin to 4.85 to 17.04 nats, a temperature of 1.3 cannot reach the alternative, so the algorithm stays fixed while every other position varies more: the phrasing growth of Figure 3. Where the forking token is contested, temperature sharpens or flattens the same two or three known algorithms at the rate the forking-token logits predict; Prim on minimum spanning tree weight rises from 0.07 at T = 0.3 to 0.31 at T = 1.3. Where the model reaches the decision through many openings, as Llama does on the grid task, no law at a single token captures it.

A tight temperature with top-k 10 gives one idea in a few phrasings, and a loose one gives the same idea, or the same few ideas, in more phrasings. This reconciles the finding with reports that temperature above 1 raises algorithmic diversity among correct programs: on contested tasks it moves mass between known algorithms, on decided tasks it does not, and a diversity evaluation that pools tasks sees an average of the two. Nor is the instruct default the base model's average answer. Post-training moved and sharpened one token, often promoting the base model's second or third choice, and left the repertoire unchanged.

Controls that act upstream of the fork, such as context that implies an algorithm, a prompt that lists approaches and then picks one, or perturbations of the task specification states, do change the algorithm. They move it to the second choice the model already knows, at a cost in correctness. The audits found no route from any control applied to single samples to a correct novel algorithm. Inside program search, targeting the forking token was not reliably better than forcing a token at a random position, so the account locates the decision without yet telling a search where to spend its randomness.

Limitations

What the paper states it does not show.

  • The headline contrast ran in one 8-bit engine. The contrast between the push and temperature ran only in an 8-bit (W8A8) engine and was not rerun in bfloat16. The push alone changes the algorithm in bfloat16 at the same absolute push norm, but the paired contrast was not repeated, and it pools two tasks, with the grid task moving only 2.50 of 20 seeds.
  • One main model. Most results come from one model, Qwen3-8B, in non-thinking mode.
  • The law's generality is an open question. The composed law was tested on three held-out units in two other families; two passed and Llama's grid task failed, below the four held-out units the preregistered claim required. It was also not clearly better than the flat law, a baseline that predicts no change (four of six units, sign test p = 0.34), which means that much of its accuracy reflects how little temperature moves these units.
  • The temperature null bounds the change rate; it does not make it zero. The null on shared seeds rests on 20 seeds per task, which bounds the change rate per seed below 0.17 per task, not at zero, and it ran with 8-bit linear layers. The bfloat16 fork margins and the grid sweep with independent samples agree with it, but the thinking-mode evidence is limited to shortest path and a 10-seed grid arm.
  • Short, well-known tasks. The tasks are short, well-known programming problems whose solutions are likely memorised, with catalogues of three to ten known algorithms; the conclusions may not hold for open-ended programs or for problems without a textbook solution.
  • Mixed engines. Experiments ran on different engines (bfloat16 and 8-bit linear layers, vLLM and Hugging Face). Push escapes reproduced in bfloat16, but pushed cells showed precision sensitivity at the level of single streams.
  • Phrasing clusters depend on a threshold. They depend on a Jaccard threshold over AST shingles with normalised identifiers, and the growth was driven mostly by the grid task.
  • Some numbers are descriptive only. Labellers were gated per task, but the gate failed by its strict criteria for the decoding experiment with independent samples and for the agreement between runtime and AST labels on the path tasks (κ = 0.753), and the expansion-order tracer used for the ban of five names failed its gold gate, so those numbers are descriptive.
  • Novelty in program search rests on manual reads. At most one LLM judge family passed its control gate there, short of the two the bin-packing rule required, and the eight candidates of one search's reader, which the one gated judge also called new, were not reproduced by the replication.
  • The geometry is correlational. The map built from names is confounded by lexical overlap between algorithm names.
  • No certified mechanism. Fitted subspace edits at the fork moved the algorithm without passing the controls that would make them a variable of the model, so a certified mechanism for the choice is still missing.
